Version 1 stays. Changes since the format was published, all listed for T07 and T08:

- The group event files (`read`, `backup`, `data-transfer`, `window`, `export-card`) now keep only events an invoke caused. - Scenario files exist for `end-of-game`, `backfill-running`, `backfill-done`, `in-game` and `challenges-loaded`. Each line has `cause` `"scenario"`.

## Per-state recording

`bun parity/record-states.ts` (run after `record-ipc.ts`) runs all 62 states of `states.ts` in trunk Electron with the seam recording every renderer invoke. It writes `states/<id>.json` (each call's arguments, method and the case that answers it), records 6,226 calls in total and adds 16 `state-<hash>` cases where no case had those arguments, and lists the ids in `manifest.json`. Proof: `states/champions-expanded.json` holds `getAugmentStats [26]`, `getChampionItemStats [26]` and `getChampionMatchHistory [26,5,0]`. `backfill-toast-done` and `backfill-toast-error` timed out on their toast text and carry an `error` field with the calls made until then. `backfill-toast-done` passed once on an earlier rerun, so it is flaky. T04's overlays states are not in this base and record once they are. Two state recordings were not compared byte for byte.

## Verify, perf

`bun parity/record-ipc.ts --timing --repeat 50` ran twice and `--compare` printed `timing stable`: no channel's median moved more than 20% beyond the 0.25 ms jitter floor. 49 channels have timing, the read-only ones. Medians are quantized to 0.1 ms by the renderer clock. Examples (ms, run 1 / run 2): `app:version` 0.1 / 0.1, `db:match-history` 1.1 / 1, `db:match-filters` 1.3 / 1.2, `db:dashboard` 1.2 / 1. Slowest: `db:global-stats` 16.4, `db:teammate-detail` 14.4, `db:teammate-group-detail` 8.3. File: `parity/out/golden/timing.json`.
