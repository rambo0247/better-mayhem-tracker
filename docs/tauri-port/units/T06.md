## Method, and what each number can and cannot see

- **Electron source.** The v1.2.1 release assets, `gh release download v1.2.1` (`BetterMayhemTracker-mac-arm64.zip` unpacked with `ditto`, `BetterMayhemTracker.exe` on Windows). Not a local `npm run dist:mac`. The zip's `.app` is 251,096 KB by `du -sk`, which matches the spike's 245 MB. The operator's installed app is never started, signalled, or measured, and every process is picked by the pid the probe spawned, never by name.
- **Run folder and data.** Each Electron run copies the fixture (`parity/snapshots/fixture`, or any `--data` folder) into a fresh `--user-data-dir`. Tauri runs are below. In the copy only, `auto_update` is `false`, `show_release_notes` is `false`, `last_run_version` is `1.2.1`, and `auto_start*` is absent. A newer release would otherwise replace the scratch app mid-run, and a login item would write the operator's LaunchAgent label. `--data none` starts on an empty folder for a runner with no fixture.
- **Isolation, a deviation from "through run-electron.ts".** `run-electron.ts` runs the unpackaged build through Playwright with `--disable-gpu`, which is not what a player runs. A packaged app cannot load `seam.cjs` (the fuses disable `NODE_OPTIONS` and CLI inspect), so nothing would hide the League client from it. On macOS the packaged app therefore runs under `sandbox-exec` with a Seatbelt profile: `(allow default)`, deny all file access to `/Applications/League of Legends.app`, `/Users/Shared/Riot Games`, and the real data folders, deny exec of `/bin/ps`, and deny writes under `~/Library/LaunchAgents`. The home in the profile is the user database's (`os.userInfo().homedir`), not `$HOME`, which a Tauri run moves. A process under a profile cannot start Chromium's own sandbox, so Electron runs with `--no-sandbox`. Still different from production: the GPU, the packaged code path, the network and the asar are production's, but Chromium's helper sandbox is off, and the client reads as "unreadable" rather than "closed", so the poller tries and fails `ps` where production finds no lockfile. For Electron, `--isolation none` skips the profile and instead waits for no League client process. Tauri refuses it. `run-electron.ts` was not used for the numbers. `perf.ts` also stops before every launch while a League game runs (`waitForNoGame`, same 30 s poll and 2 minute wait as `wait-no-game.sh`) and marks a run invalid if a game starts during it.
- **Memory.** `footprint -p <pids> -j <file>` over the main process and every helper, read as its `total footprint` (`phys_footprint`, what Activity Monitor calls Memory). `man footprint` says it de-duplicates objects mapped into more than one of the processes given, so this is less than the per-process sum: 299,406,640 bytes against 300,487,984 in the recorded 4-process sample, 1.1 MB. `ps -o rss` is summed beside it. Windows sums `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate` over the tree, with working set beside it. Median of 5 samples 10 s apart, taken 60 s after first content, window up (or hidden, below), client absent. RSS is 2 to 4 times footprint because it counts the shared system frameworks every process maps, so it is not the comparison number.
- **Attribution by public facts only.** Electron helpers are children of the spawned pid, named by `--type=` (`renderer`, `gpu-process`, `utility` with the network service sub-type). Their command lines also carry `--user-data-dir`, and any process outside the tree that carries this run's folder fails the run as a stray. A WebKit helper is an XPC service whose parent is launchd, so it counts only if it did not exist before the spawn, started at or after it, and either holds a file that names the app (the GPU helper's cache folder is named after the executable, the networking helper's `~/Library/WebKit/<bundle id>` data) or is the one expected new content helper, or the nearest by pid. More than one candidate with none tied to the app makes the run invalid as ambiguous. The helper set is frozen at first content, so a second copy of the shell started later cannot join it. No process-responsibility or TCC API is used.
- **Invalid runs record no number.** A missing main, renderer, GPU or network helper, a frozen helper that disappears, a stray, an ambiguous WebKit set, a failed `footprint` read, an app exit, a game start, or no first content in 30 s. The summary lists the reasons.
- **Launch to first content.** Spawn is `performance.timeOrigin + performance.now()` taken in the probe just before `spawn`. For Electron the probe connects to `--remote-debugging-port`, auto-attaches to every page, and injects a script that records when the first `button.group.relative.flex.w-full` (the same selector `states.ts` waits for, with a test that keeps them equal) is in the DOM with a non-empty box, then two animation frames later. The headline is the two-frame time when it arrived, else the DOM time. It cannot see what a covered window withholds: Chromium stops animation frames for an occluded window, so a covered window reports the DOM time (the run records `row-in-dom` and the page's `visibilityState`). It cannot see icons or images, which load after the row. The DevTools port opens after the window's page already exists (about 570 ms after spawn in a run), so the injected script attaches to a page that is already loading. A run is flagged when the row was already there at attach, which would make the time an upper bound. The probe adds a little memory (a DevTools server, a detached session). Each run starts from a fresh profile, so no Chromium cache is warm, but the OS file cache cannot be dropped without `sudo purge`, so launches are warm at the disk level.
- **Tauri.** A release build compiles no data-root override (T09), so it opens `dirs::config_dir()/better-mayhem-tracker`. On macOS that is `$HOME/Library/Application Support`: dirs 7.0.0's `config_dir` is `home_dir().join("Library/Application Support")`, and dirs-sys 0.5.0's `home_dir` returns `$HOME` when it is set and not empty, else `getpwuid_r`. So `--app tauri` runs the binary with `HOME=<run>/home` and copies the fixture to `<run>/home/Library/Application Support/better-mayhem-tracker`. `--tauri-profile lane` is for any other Cargo profile: it also sets `BMT_DATA_ROOT=<run>/userdata`, which T09's lane build reads, and copies the fixture there. The binary also gets `BMT_PERF=1` and `BMT_PERF_LOG=<run>/perf.log`. Five guards stand behind the redirect:
  - The Seatbelt profile is always on for Tauri, and `--isolation none` is refused.
  - WebKit keeps `~/Library/WebKit/<bundle id>` under the real home whatever HOME says, which the live run below confirmed. So the binary must carry `com.better-mayhem-tracker.perf`, set by `tauri build --config parity/perf/tauri-perf.conf.json`, and the probe refuses a bundle whose `Info.plist` has any other id, before it does anything else. `prove.ts` launches through the same check and HOME.
  - A run counts only when the app proves it opened the copy: `<data root>/logs/main.log` exists and is not empty, and the `first-content N ms` line ends with `row=<JSON string>` whose kills, deaths and assists are the fixture's newest game. `--data none` is refused, because nothing could be proven. The `first-paint` fallback is gone.
  - On Windows the folder comes from `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` (dirs-sys 0.5.0), which ignores APPDATA. Tauri runs there are refused unless `CI` and `GITHUB_ACTIONS` are both `true`. On a runner the probe copies the fixture into that folder, and clears it between runs only when it holds the `.bmt-perf-made` marker the probe left, so a folder with a player's data stops the run instead. Windows Tauri was not run here.
  - Copy and real-folder refusals throw out of the run and stop the sweep. The catch-all that turned them into a run in the bare run folder is gone.
- **Hidden idle.** `--scenario hidden-idle` launches each app with `--hidden`, the login-item launch, and measures idle the same way with no window. It writes `<apps>-hidden-idle-<mac|win>.json`. Electron 1.2.1 creates the window with `show: false` and the page still loads, so first content is still timed and the row still checked. The page reports `visible` there, because Electron's `paintWhenInitiallyHidden` defaults to on, so the hidden run does not note visibility. I did not confirm the window stayed off screen: Screen Recording is not granted. For Tauri the same proof applies, so T10's hidden launch must still print the `first-content ... row=` line.
- **Load.** The probe samples the 1-minute load average and CPU idle every 2 s for the whole sweep, records every sample, and gives each run its own median. On macOS both come from `top -l 31 -s 2 -n 0`, replaced every minute, because `os.cpus()` times did not move over 6 s on Darwin 27.2.0, in Bun and in Node. Each top process's first CPU line is a short-interval reading, not a full 2 s one, and is dropped. Windows uses `os.loadavg()` (always 0 there) and `os.cpus()` deltas. The gate is the median CPU idle, since Windows reports a load average of 0: a sweep whose median idle is below 30% writes `<name>.refused.json` with the raw runs, prints no numbers, and exits 1. Per-run progress lines print only ok or INVALID, and numbers appear only after the gate passes. `--min-cpu-idle <share>` is the only override, and the JSON's `load` block records `minCpuIdle`, `minCpuIdleFromFlag`, `medianCpuIdle`, `medianLoad1` and `passed`. The 30% is provisional, see Fix round 2.
- **Command line.** `parseArgs` in strict mode: an unknown flag, a positional, or a bad value exits 2 with the usage.
- **Interleaving.** With two apps, run `i` goes A then B on even `i` and B then A on odd `i`. Each run uses a fresh profile and waits 3 s after the previous app has gone. A true cold start (dropped OS cache) is not possible without root.
- **Spread** is (max - min) / median.

## Deviations and decisions for the root

- Electron runs packaged under Seatbelt with `--no-sandbox`, not through `run-electron.ts`. Reasoning above. The root can ask for the harness variant instead, but it runs with `--disable-gpu` and is not a shipped configuration.
- `ulimit -u 200` cannot be applied here: the operator's user already runs about 490 processes, so any fork fails under that cap. The probe spawns one app and at most a few helpers per run, never injects `-r`, and kills only pids it started.
- Windows needs a fixture artifact (`parity-fixture`) to measure real first content. Nothing uploads one yet (decision E2).
- T27 (or whichever unit owns `page_event`) must end the `first-content` line with ` row=` and `JSON.stringify` of the first Match History row's `innerText`, on stdout and in `BMT_PERF_LOG`.
