## Build

- [x] `parity_driver.rs`, compiled only with `--features parity-driver`. A release build with the feature fails with `compile_error!("the parity-driver feature is for debug builds only")`, with and without `CARGO_PROFILE_RELEASE_DEBUG_ASSERTIONS=true` (exit 101 both, `parity/out/evidence/release-feature-refused.log` and `release-debug-assertions-refused.log`). It listens on `127.0.0.1:0` and prints `bmt-parity-driver-v1 listening 127.0.0.1:<port>`. It refuses to start without a `BMT_PARITY_TOKEN` of at least 16 characters, refuses a non-loopback peer (403) or a request without `Authorization: Bearer <token>` (401, constant-time compare), and keeps the page on the origin it opened at. The primitives are `eval`, `mouse`, `key`, `wheel`, `resize`, `viewport`, `navigate`, `reload`, `snapshot`, `info`, `quit`. The plan's verbs `click`, `hover`, `type`, `key`, `scroll`, `resize`, `navigate`, `dom`, `geometry` are served by `run-tauri.ts` through `drive.ts --run`, the control protocol `run-electron.ts` serves, so one definition of each verb drives both apps.
  - macOS. `eval` is `callAsyncJavaScript` in the page world. Mouse and key events are `NSEvent`s handed to the `WKWebView`, never the window, so AppKit never makes the window key or activates the app. Points are offset by WebKit's `obscuredContentInsets`. `wheel` scrolls from script.
  - Windows. Everything is DevTools Protocol through `CallDevToolsProtocolMethod`: `Runtime.evaluate`, `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent`, `Emulation.setDeviceMetricsOverride`, `Page.captureScreenshot`.
  - Under the feature the app is an accessory app on macOS, never focused or activated, at 40,40, above other windows, with an `NSProcessInfo` activity against App Nap and idle display sleep, and a private store. `BMT_PARITY_ACTIVATION=regular` and `BMT_PARITY_COVER=1` exist only for the two proofs the root asked for.
- [x] `snapshot/mac.rs` and `snapshot/win.rs`, outside the feature for T25. On the operator's display WebKit hands back `sRGB IEC61966-2.1`.
- [x] `run-tauri.ts` launches the driver build with a fresh token, an environment built from a short host list plus the run's own values, `TZ=America/New_York`, `LANG=en_US.UTF-8`, `-AppleLanguages (en-US)`, WebView2 switches matching `run-electron.ts`, the frozen page clock, and the state's viewport. It fails when the page's zone is not New York. It stops the app on every failure path.
- [x] `replay-api.js` answers `window.api` from T05's goldens. The running state's own call list (`states/<id>.json`, T05 `2ce6430`) answers first by exact arguments. A call the list lacks gets FORMAT.md version 1's rule (equal canonical arguments, lowest `seq`, a write group behind one cursor per channel, then `default`) and counts as an `unlisted` miss. A `default` answer is a miss, and no answer throws `ReplayMiss`. Settings written with a golden are read back across the state's reload.
- [x] `tauri-ci.yml` builds release and fails when the binary holds `bmt-parity-driver` or `BMT_PARITY_TOKEN`. The positive control builds `--debug --features parity-driver` and must find `bmt-parity-driver-v1`.
