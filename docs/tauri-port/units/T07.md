## Build

- [x] `parity_driver.rs`, compiled only with `--features parity-driver`. A release build with the feature fails: `cargo check --release --features parity-driver` stops on `compile_error!("the parity-driver feature is for debug builds only")`, exit 101 (`parity/out/evidence/release-feature-refused.log`). It listens on `127.0.0.1:0` and prints `bmt-parity-driver-v1 listening 127.0.0.1:<port>`. It refuses to start without a `BMT_PARITY_TOKEN` of at least 16 characters, and refuses any request from a non-loopback peer (403) or without `Authorization: Bearer <token>` (401, constant-time compare). Deviation from the plan's verb list, per the root's design: the driver offers primitives (`eval`, `mouse`, `key`, `wheel`, `resize`, `viewport`, `navigate`, `reload`, `snapshot`, `info`, `quit`). The plan's verbs `click`, `hover`, `type`, `key`, `scroll`, `resize`, `navigate`, `dom`, `geometry` are served by `run-tauri.ts` through `drive.ts --run`, the same control protocol `run-electron.ts` serves, so one definition of each verb drives both apps.
  - macOS: `eval` is `callAsyncJavaScript` in the page world, so promises are awaited and exceptions come back with WebKit's message. Mouse and key events are `NSEvent`s handed to the `WKWebView` itself, never through the window, so AppKit never makes the window key or activates the app. Points are offset by WebKit's public `obscuredContentInsets` (see Findings). `wheel` scrolls from script: a wheel `NSEvent` can only be built from a `CGEvent` at a screen position, which WebKit then reads in the wrong space for a window not under the real pointer.
  - Windows: everything is DevTools Protocol through `ICoreWebView2::CallDevToolsProtocolMethod`, the channel Playwright uses for Electron: `Runtime.evaluate` with `awaitPromise`, `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent`, `Emulation.setDeviceMetricsOverride`, `Page.captureScreenshot`.
  - Every call that waits for the main thread waits on a channel with a timeout, so a failed downcast cannot hang a request.
  - Under the feature the app is an accessory app on macOS (no Dock icon), `activate_ignoring_other_apps(false)`, `focused(false)`, always on top, at 40,40, with an `NSProcessInfo` activity held against App Nap and idle display sleep, and a private (`incognito`) store. It never calls focus or activate. `BMT_PARITY_ACTIVATION=regular` keeps the Dock icon and `BMT_PARITY_COVER=1` opens a screen-sized normal-level window of the app's own, both only for the two proofs the root asked for.
  - Data and clock injection for later units: the driver takes any initialization script from `BMT_PARITY_INIT`, any renderer from `BMT_PARITY_RENDERER_DIR`, any asset cache from `BMT_PARITY_ASSETS`. The T09 data folder and a Solid build's clock go through the same variables with no driver change.

## Findings for the root

1. **macOS 26 gives the T01 window's webview 32 px less than its content size.** A 1280x820 window lays out a 1280x788 page. WebKit reports the strip as `obscuredContentInsets.top = 32` (driver `info.topInset`). Every click aimed by the view's bounds landed 32 px high until the driver offset it. Parity runs steer the window to 1280x852 so the page is 1280x820. The real app inherits a 788 px page until T10 ports Electron's hidden title bar. T10 should check it.
2. **WKWebView applies mouse moves only in the active window.** The driver never activates the app, so hover goes through script events on macOS (above). Clicks and keys sent to the view arrive as trusted events in an inactive window.
3. **WebKit's WebContent process does not inherit `TZ`.** On a `macos-latest` runner the page read `UTC`. On the operator's Mac it reads `America/New_York` because that is the system zone. `run-tauri.ts` fails a capture whose page is not in New York.
4. **`::-webkit-scrollbar { display: none }` no longer hides WebKit's scrollbars.** The kill switch now also sets `scrollbar-width: none`. Without it every scrolling page shifted 16 px. Electron's captures are unchanged by it (25 of 26 at 0 px against T02's baseline, as above).
5. **Inline style attributes are blocked by the Tauri page's CSP** (Tauri adds nonces, which turn off `unsafe-inline`). Only matters for test pages; the smoke check styles through the CSSOM.
6. **On `windows-latest` a 1280x820 page at device scale 2 does not fit the runner's screen.** The driver sets the viewport and scale with `Emulation.setDeviceMetricsOverride`, as Playwright does. T02's Windows Electron baseline uses a real window with `--force-device-scale-factor=2` and may be shrunk the same way (unverified, no fixture run yet).
7. **T05's cases miss the calls the renderer makes**, so replay serves `default`. `replayCalls` in each state's meta file lists them.
8. **`ulimit -u 200` cannot be set on this Mac.** The account owns about 489 processes, and macOS counts all of them, so forks fail. The owner capped growth at the current count plus 200. Sent to the root at the time.
9. Commit `34b7160` also carries the hover fallback in `run-tauri.ts`; its message does not mention it. Rewording it needs a force-push, which the permission system refused.
10. Untracked `.DS_Store` at the worktree root is Finder's, not this unit's, and is not committed.
