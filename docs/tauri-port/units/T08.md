## What later units change

A porting unit replaces bodies only. Each body is `pub async fn <name><R: Runtime>(ctx: Ctx<R>, <args>) -> CommandResult<T>` in `tauri/src-tauri/src/commands/<domain>.rs` (or `commands/<domain>/mod.rs`). `ctx.app` reaches managed state, `ctx.window` is Electron's `event.sender`, `ctx.now_ms()?` reads the clock that golden replay freezes, and `ctx.blocking(|| ...)` runs database work off the async workers. Reject with `CommandError::thrown(message)` or `CommandError::named(name, message)`; a `rusqlite::Error` converts with `?` and keeps the name `SqliteError`. A panic rejects the call. Managed state goes in the domain's `Hooks` through `commands::Domain::register`, which `lib.rs` `app_builder` runs for the app and the golden replay alike, and per-case golden state through `Domain::before_golden_case`. See Surface changes below. Emit through `events::<name>(&app, &payload)`. Any edit to `commands/mod.rs`, `types.rs`, a type, `events.rs`, `bindings.ts`, or `api.ts` is a contract change and goes to the root; `contract-check` and the bindings freshness step fail on it.

## Build

- [x] Every request and response type is defined once, in Rust, with `api.ts`'s names and casing per field. Rows read from SQLite are snake_case with no `rename_all`; shapes built in JavaScript are `rename_all = "camelCase"`. The three mixed structs (`SeasonChampion`, `GlobalChampionDetail`, the `GlobalStats` champion row, here `GlobalChampionRow`) are camelCase with `#[serde(rename = "champion_id")]`. `CardSpec` and `BackfillLimit` are internally tagged with `rename_all_fields = "camelCase"`; `#[ts(optional)]` on a struct-variant field works in ts-rs 12.0.1 (the open item in the design). `BackfillResult | { error }` is an untagged `BackfillOutcome`. `extends MatchListItem` is `#[serde(flatten)]`. `?:` from a JavaScript object is `#[ts(optional)]` plus `skip_serializing_if`; `?:` on a database row (`GameRecord.puuid`, `is_remake`, `favorite`) has no skip, because the row always carries the column. Integers are `i64`; averages, scores, shares, percentiles, challenge values and live-client fractions are `f64`.
  - Bug for bug: Electron's match list selects the `games` row whole, so every `MatchListItem` on the wire carries `puuid`, which `api.ts` does not declare. The Rust struct carries it with `#[ts(skip)]`, so the wire matches Electron and the TypeScript matches `api.ts`.
  - Erratum: the plan's `MatchSummary` is `MatchListItem`.
- [x] `export_bindings` writes `bindings.ts` with ts-rs 12.0.1 and `Config::new().with_large_int("number")` in code (no `bigint` in the file). ## Verify, perf

- Metric. Invoke round trip of a Tauri stub (`getVersion`, which rejects `not ported`) against Electron's `getVersion`.
- Probe. `bun parity/invoke-probe.ts --data fixture --timing`: 1,000 calls per app in ten alternating rounds of 100. Both pages run frozen clocks and WebKit rounds `performance.now()` to 1 ms, so each round is timed from bun: the evaluate of 100 awaited calls less the same evaluate with none, divided by 100.
- Baseline. At code-ready T05's `timing.json` was not yet written, so Electron was measured in the same run. It exists now: `app:version` `default` median 0.1 ms, p95 0.3 ms, n 50. The verifier measured a 0.177 ms delta at `4000491`.
- Result. Run 1: Tauri 0.226 ms, Electron 0.060 ms, delta 0.166 ms. Run 2: Tauri 0.222 ms, Electron 0.071 ms, delta 0.150 ms (`parity/out/evidence/invoke-timing*/invoke-probe.json`). Rule: fail above 0.5 ms. PASS, measured. The first round of each run is warm-up (2.1 ms Tauri, a negative Electron value from the subtraction) and the median of ten rounds is not moved by one outlier. What sets the Tauri number is inferred, not traced: a custom-protocol fetch, JSON both ways, the async command's task spawn, and the rejection path.
