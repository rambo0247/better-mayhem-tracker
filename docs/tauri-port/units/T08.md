## What later units change

A porting unit replaces bodies only. Each body is `pub async fn <name><R: Runtime>(ctx: Ctx<R>, <args>) -> CommandResult<T>` in `tauri/src-tauri/src/commands/<domain>.rs`. `ctx.app` reaches managed state, `ctx.window` is Electron's `event.sender`, and `ctx.now_ms()` reads the clock that golden replay freezes. Reject with `CommandError::thrown(message)`, which the page sees as `Error invoking remote method '<channel>': Error: <message>`. Managed state goes in `lib.rs` `app_builder`, which both the app and the golden replay build from. Emit through `events::<name>(&app, &payload)`. Any edit to `commands/mod.rs`, `types.rs`, a type, `events.rs`, `bindings.ts`, or `api.ts` is a contract change and goes to the root; `contract-check` and the bindings freshness step fail on it.

## Build

- [x] Every request and response type is defined once, in Rust, with `api.ts`'s names and casing per field. Rows read from SQLite are snake_case with no `rename_all`; shapes built in JavaScript are `rename_all = "camelCase"`. The three mixed structs (`SeasonChampion`, `GlobalChampionDetail`, the `GlobalStats` champion row, here `GlobalChampionRow`) are camelCase with `#[serde(rename = "champion_id")]`. `CardSpec` and `BackfillLimit` are internally tagged with `rename_all_fields = "camelCase"`; `#[ts(optional)]` on a struct-variant field works in ts-rs 12.0.1 (the open item in the design). `BackfillResult | { error }` is an untagged `BackfillOutcome`. `extends MatchListItem` is `#[serde(flatten)]`. `?:` from a JavaScript object is `#[ts(optional)]` plus `skip_serializing_if`; `?:` on a database row (`GameRecord.puuid`, `is_remake`, `favorite`) has no skip, because the row always carries the column. Integers are `i64`; averages, scores, shares, percentiles, challenge values and live-client fractions are `f64`.
  - Bug for bug: Electron's match list selects the `games` row whole, so every `MatchListItem` on the wire carries `puuid`, which `api.ts` does not declare. The Rust struct carries it with `#[ts(skip)]`, so the wire matches Electron and the TypeScript matches `api.ts`.
  - Erratum: the plan's `MatchSummary` is `MatchListItem`.
- [x] `export_bindings` writes `bindings.ts` with ts-rs 12.0.1 and `Config::new().with_large_int("number")` in code (no `bigint` in the file). It writes every reachable declaration sorted by name, `CHANNELS`, `RendererEvents` (`void` for `lcu:games-updated`), and `createCommands(transport)`, one positional wrapper per command whose named keys are heck's lowerCamelCase, the function `#[tauri::command]` uses. Commands returning `()` resolve `undefined`, as Electron's do. `--check` fails on a stale file. It is gated behind the `export-bindings` feature so `tauri build` never compiles it.
- [x] All 61 commands are registered under their Electron channel names through `#[tauri::command(rename = …)]`, async, generic over `R: Runtime`, with `AppHandle<R>` and `WebviewWindow<R>` injected. Every body answers `{ name: "Error", message: "not ported", code: "NOT_PORTED" }`. T01's `page_event` is folded into the one `generate_handler!`. All 11 emitters are real and send to the window labelled `main` only.
- [x] `api.ts` builds the preload's object: the 61 wrappers over a transport, the 11 `on*` subscriptions on `getCurrentWebviewWindow().listen` with a synchronous unsubscribe that also works before `listen` resolves, and `platform` and `locale` from `window.__BMT_BOOT__`, which `lib.rs` injects as an initialization script (`darwin`/`win32`; `locale` is `undefined` until T09). `ElectronAPI` is imported by relative path and `createApi` is typed as it, so `tsc` checks the whole object.
- [x] `contract-check.ts` compares `INVOKE_CHANNELS` and `RendererEvents` names as text, then writes one assertion per method's arguments, result, and per event payload, and runs `tsc --noEmit` on them (TypeScript 7 has no JS compiler API). A type-level diff names each mismatched path: missing or extra field, optional on one side, null or undefined on one side, argument count. All mismatches are joined into one literal, because tsc reports one member of a failing union.
- [x] `golden.rs` builds the mock app through `app_builder` per case group, over a fresh copy of `BMT_GOLDEN_DATA` named by `BMT_DATA_ROOT`, with the manifest's frozen clock. It replays each golden through `tauri::test::get_ipc_response`, so channel names, argument keys and `Option` handling run the real IPC path, and compares by `canon.ts`'s rules ported to Rust (sorted keys, numbers as parsed values, `CLOCK_FIELDS` masked, `void` equal to `null`). The Rust `CLOCK_FIELDS` is checked against `parity/canon.ts` when that file exists. It also runs every recorded argument, result and event payload through its Rust type and back, and fails on any change. Without goldens (CI) every row reads `no golden` and only the self-check runs.
  - Not compared at T08, by design: per-case `events`, `effects` and `files`. They need the emitting units (T17 to T21) and are wired there.

## Verify, perf

- Metric. Invoke round trip of a Tauri stub (`getVersion`, which rejects `not ported`) against Electron's `getVersion`.
- Probe. `bun parity/invoke-probe.ts --data fixture --timing`: 1,000 calls per app in ten alternating rounds of 100. Both pages run frozen clocks and WebKit rounds `performance.now()` to 1 ms, so each round is timed from bun: the evaluate of 100 awaited calls less the same evaluate with none, divided by 100.
- Baseline. T05's `timing.json` was not in T05's output folder when read, so Electron was measured in the same run.
- Result. Run 1: Tauri 0.226 ms, Electron 0.060 ms, delta 0.166 ms. Run 2: Tauri 0.222 ms, Electron 0.071 ms, delta 0.150 ms (`parity/out/evidence/invoke-timing*/invoke-probe.json`). Rule: fail above 0.5 ms. PASS, measured. The first round of each run is warm-up (2.1 ms Tauri, a negative Electron value from the subtraction) and the median of ten rounds is not moved by one outlier. What sets the Tauri number is inferred, not traced: a custom-protocol fetch, JSON both ways, the async command's task spawn, and the rejection path.
