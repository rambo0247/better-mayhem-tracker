## Build

- [x] Port `paths.ts`. The root is `dirs::config_dir()/better-mayhem-tracker`, which is `~/Library/Application Support/better-mayhem-tracker` and `%APPDATA%\better-mayhem-tracker`, never the Tauri identifier folder. `data/`, `backups/`, `logs/` and `asset-cache/` are made on first use, as `ensureDir` does. `BMT_DATA_ROOT` overrides the root in debug and parity-driver builds only, under `cfg(any(debug_assertions, feature = "parity-driver"))`, per the root's decision after T08's review. Electron 1.2.1 has no override, and in a release build one would let any process environment redirect a player's database and backups. A release build compiles neither the override nor `data_guard.rs`. `paths::tests::a_release_build_ignores_the_override` drives `root_for` with the release kind. `tauri-ci.yml` fails a release binary that contains the string `BMT_DATA_ROOT`, with the parity-driver build as the positive control. A local release build had no `BMT_DATA_ROOT`, `bmt-parity-driver` or `refused to start`, and the driver build had `BMT_DATA_ROOT`. An empty value counts as unset. The `Paths` value is managed state, `ctx.app.state::<Paths>()`. `app_builder` calls `Paths::resolve()` each time it builds an app, and nothing caches the root per process, so golden replay can build one app per root in one process (`tests/paths_env.rs`).
- [x] `data_guard.rs`, compiled only in debug and parity-driver builds. A debug or parity-driver build whose root is the real folder, or inside it, prints why and calls `process::exit(78)`. `Paths::at` runs it before it stores the root, and `run()` resolves `Paths` first, so nothing is created or opened before it. Release builds skip it.
  - Deviation from the plan line, per the root's decision. There is no `BMT_ALLOW_REAL_DATA` escape. The guard cannot be bypassed in debug and parity builds.
  - How it resolves. It makes the root absolute and applies `..` to the text. It walks the root with its own resolver, which follows symlinks even when they dangle, applies `..` to the folder actually reached, and gives up (and refuses) past 32 links. It compares names case-folded, with `to_uppercase().to_lowercase()`, so the Kelvin sign and long s fold as on APFS and NTFS. It strips Windows `\\?\` prefixes. It also matches by identity. Any ancestor of the root that is named `better-mayhem-tracker` and whose parent has the config folder's device and inode (Windows: the same canonical path) trips it. That catches firmlinks such as `/System/Volumes/Data/private/...`, which no symlink explains.
  - Which real folders. `dirs::config_dir()`, the passwd home's `Library/Application Support` on macOS (`$HOME` can move the first), and `%APPDATA%` on Windows. With none known it refuses.
  - It never stats the real folder itself. It stats the root's own path and the config folder.
  - Known limit. It is a check at resolve time. A symlink swapped in after it runs is not caught.
- [x] Port `log.ts`. The line is `YYYY-MM-DD HH:MM:SS.mmm LEVEL msg\n` in local time (chrono `Local`, which honors `TZ`). It is appended synchronously a line at a time. The roll to `main.old.log` happens when `size + line > 2 MiB`, and a failed rename stops further rollovers until the next launch. `log::info`, `warn` and `error` also print to stdout or stderr, as `console.*` did. A panic hook writes `FATAL <panic info>` and then chains to the previous hook.
  - Decision for the root. The version line reads `Better Mayhem Tracker 1.2.1, Tauri 3.0.0-alpha.6, Darwin 27.2.0`, where Electron writes `Electron 44.4.5`. Writing "Electron" from a Tauri build would mislead a bug report. Lane 1 needs the runtime token normalized, or the operator can ask for Electron's text.
  - Not ported yet. Electron's `watchRenderer` forwards the page's `console` warnings and errors, `render-process-gone`, and `preload-error` into the log. That needs a page hook plus a command outside the 61-channel contract. Left for T27 or the root.
  - `log::start` runs in `run()` right after `Paths::resolve()`. T10 must move it behind the single-instance check, as Electron does.
- [x] Port `locale.ts`. Deviation from the plan's `sys-locale`, with the evidence. Electron's `app.getSystemLocale()` documents `[NSLocale currentLocale]` on macOS (language plus region, `fr-FI`) and the regional format on Windows (`fi-FI`) (`node_modules/electron/electron.d.ts`, `getSystemLocale` and `getPreferredSystemLanguages`). `sys-locale` returns the display language on both platforms, which would move week boundaries (`firstDayOfWeek(systemLocale())` in `db/matches.ts`) and number formats. `locale.rs` reads `CFLocale::current().identifier()` with `_` swapped for `-`, as Electron does, and `GetUserDefaultLocaleName` on Windows, cut at `_` for an alternate sort order (inferred, untested). It then canonicalizes the tag as `Intl.getCanonicalLocales` does, returning `None` where Intl throws. Aliases such as `iw` to `he` are not mapped. The value reaches `window.api.locale` through `boot_script`.
- [x] Port `install-location.ts`. `APP_DISPLAY_NAME` and `WINDOWS_EXE_NAME` carry over. On Windows the durable exe is `current_exe()`. On macOS the `.app` bundle three levels up counts unless it is under `/AppTranslocation/` or `/Volumes/`. "Packaged" is `!cfg!(debug_assertions)`, so a debug build never has a durable install, as an unpackaged Electron run does not.
- [x] Port `security.ts`.
  - CSP in `tauri.conf.json`, from `electron.vite.config.ts`. `default-src 'none'`, `script-src 'self'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' data: asset: http://asset.localhost`, `font-src 'self' data:`, `connect-src 'self' ipc: http://ipc.localhost`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. `file:` is dropped, since Tauri serves from its own scheme. The `asset:` sources are ready for T22.
  - `dangerousDisableAssetCspModification: ["style-src"]`. Tauri would add nonces to `style-src`, and a nonce makes the browser ignore `'unsafe-inline'`, which would break the inline style attributes the UI writes. `devCsp` adds `'unsafe-inline'` scripts and the Vite websocket for `tauri dev`.
  - `security::harden` sets the window's `on_navigation` and `on_new_window`. It allows `tauri://localhost`, `http(s)://tauri.localhost`, `about:blank`, the dev server's origin in debug builds, and the parity renderer's origin only with the driver feature. Anything else is refused, and a web page goes to the default browser, as `will-navigate` and `setWindowOpenHandler` do.
  - `open_external_url` allows `http` and `https` only, and logs `WARN Refused to open external URL: <url>` otherwise.
  - Electron's permission handler denies everything. wry grants a page no camera, microphone, geolocation or notification permission on its own, so it has no port. No `<webview>` exists in Tauri.
- [x] Port the `app:*` channels this module owns. `getVersion` returns the root `package.json` version (`include_str!`, parsed once), as `app.getVersion()` does. `tauri.conf.json` `version` points at the same file, so the bundle's version matches. `openUrl` and `openLogsFolder` go through the `Effects` seam on `Host`: `System` calls `tauri_plugin_opener::open_url` and `open_path`, and `Recorded` keeps a list for golden replay. The plugin is not registered, so the page gains no opener permission. The `app:*` update channels stay with T24.
