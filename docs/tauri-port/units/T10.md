- [x] Tray: Show Window, separator, Quit; tooltip; `tray.png` and `tray@2x.png`. The menu opens on a left click on macOS and a right click on Windows; a double-click shows and focuses on Windows. The icons are compiled in with `include_bytes!` rather than bundle resources, because a dev or driver build has no resource folder. The macOS icon is sized back to 16 pt, Electron's size, since tray-icon forces 18 pt.
- [x] Single instance (`single_instance.rs`), taken in `run()` before Tauri builds anything. A second launch exits 0 and the first window restores, shows, and focuses. During a quit, `shell::handover_decision` decides instead (fix round 3, items 4 and 6): after a close-quit the launch is taken and the window stays away, and once the quit reaches `Exiting` the Unix listener answers `shutting down`, so the launch waits for the lock and starts fresh. On macOS and Linux the lock is an `flock(LOCK_EX | LOCK_NB)` on `<identifier>.lock` in the user's own temporary folder (`confstr(_CS_DARWIN_USER_TEMP_DIR)`, mode 0700 under `/var/folders`; `XDG_RUNTIME_DIR` on Linux), held for the process's life. A later launch sends `tauri-plugin-single-instance`'s message (the working directory, then the arguments) over `<identifier>.sock` beside it, which only the lock's holder removes and binds. The first instance reads it once the event loop is ready, runs the callback, and answers, so a launch that reaches an instance on its way out retries and takes the freed lock. With no answer in 20 s, Chromium's wait, the later launch exits 1 with one stderr line. On Windows the lock is the named mutex `Local\<identifier>-lock`, in the session namespace as Chromium's is, and a later launch sends its arguments to the plugin's window (`<identifier>-sic`) by `WM_COPYDATA` once that window exists. `tauri-plugin-single-instance` 3.0.0-alpha.3 now runs on Windows only, as that window. The identifier is `tauri.conf.json`'s in release builds. Lane builds scope it as at `ea14a14`: a `BMT_DATA_ROOT` override adds a hash of that root, and a driver build with no root adds its pid, as Electron's lock is per user data folder. The lock follows the identifier.
- [x] Close to tray per `minimize_to_tray` (any value but `"false"` hides), `--hidden`, the macOS Reopen event, the window commands, and `window:maximized-changed` read off resizes. A close with the setting `"false"` hides the window before the quit starts, as Electron's unprevented close removes it while the fetch runs.
- [x] Quit: tray Quit, Cmd+Q, a close with the setting off, AppKit's `terminate:` (the Dock's Quit and logout), SIGTERM, SIGINT, and SIGHUP, and the Windows console's Ctrl+C, close, logoff, and shutdown. Each runs the final fetch hook bounded at 5 s, then stops polling, logs `Shutting down`, runs the shutdown hooks, and exits 0. A second quit during the fetch exits at once, as Electron's second `before-quit` does. Hooks on `Shell` for T11 (setting), T20 (fetch, polling), T11/T17/T21 (shutdown), T24 (`on_put_away` for hide and minimize, and `request_quit`).
- [x] Electron 1.2.1 on the same data folder (fix round 3, item 8). After this app's own lock and before anything opens the data root, `run()` reads `<data root>/SingletonLock`, Chromium's process singleton link (`<hostname>-<pid>`). If it names this host and a live pid, the launch logs one line and exits 0, showing neither app's window. Release builds read `~/Library/Application Support/better-mayhem-tracker`, Electron's `userData`. Lane builds read only `BMT_DATA_ROOT`, and with no override skip the check, so no lane looks into a player's folder. The link is only read. **Hook for T09:** `shell::electron_user_data` becomes `paths.rs`'s root at the restack.
- [x] `terminate:`: tao's delegate has no `applicationShouldTerminate:`, so `shell.rs` adds one to the delegate's class with `class_addMethod`. It answers `NSTerminateLater` while the fetch runs. When the quit reaches `Exiting`, a block on the main run loop's common modes calls `replyToApplicationShouldTerminate:YES`. The block runs outside tao's event handler, because AppKit ends the process inside the reply through tao's `applicationWillTerminate:`, which takes the handler's lock; a reply sent with `run_on_main_thread` would wait on that lock. With no client, it runs the quit at once and answers `NSTerminateNow`. While that reply is pending, AppKit never asks the delegate again: a second `terminate:` ends the process without the shutdown hooks, and a second quit Apple event waits until the reply. So `shell.rs` also adds `terminate:` to tao's `NSApplication` subclass and installs a quit Apple event handler ahead of AppKit's (`AEGetEventHandler`, `AEInstallEventHandler`). Each takes a quit that arrives during the pending reply and runs the quit's second step; every other quit goes on to AppKit's own.
- [x] `--hidden` passes `activate_ignoring_other_apps(false)` to the builder. That is Tauri's public knob for tao's launch-time `activateIgnoringOtherApps`, so a login launch leaves the active app active.
- [x] macOS app menu equal to Electron's default menu item for item (labels, roles, accelerators), with Quit through the final fetch.
- [x] F12 and Ctrl+Shift+I toggle the devtools in every build (`devtools` feature on `tauri` and `tauri-runtime-wry`), through a page key listener and Tauri's own toggle command.
- [x] Startup order: `first_instance_started` is the first call in `setup`. A second launch hands over and exits in `run()` before Tauri builds anything, so it writes nothing. **Hook for T09:** at the restack, T09's `log::start` goes in `first_instance_started` in `lib.rs`, in place of the stand-in line `first instance started`.

## Blockers and decisions for the root

- Electron's traffic lights cannot be pictured: Screen Recording is not granted, and a native capture inside Electron is not allowed. Lane 1's Electron side stays a model until the operator decides on Screen Recording.
- Golden replay: `window:is-maximized` `maximized` fails under the mock runtime, whose `is_maximized` is always false. CI has no goldens, so CI does not fail on it. The case depends on T08's fix round item 18, per-case window-state seeding. T10's code stays as it is.
- `libc 0.2.191` is a direct dependency on Unix, for `confstr`, pinned at the version already in `Cargo.lock`. `windows-sys 0.61.2` is a direct dependency on Windows, with features the plugin already turns on.
- A lane build leaves a 0-byte `.lock` and a `.sock` per data root or pid in the per-user temporary folder. A lock file is never removed, since removing it would let a launch lock a new file while another holds the old one. macOS clears that folder on its own schedule.
- The Windows code is checked here only with `cargo clippy` for `x86_64-pc-windows-msvc` from a scratch toolchain; it is linked and run only in CI.
- On Windows, Electron 1.2.1's lock is a named mutex and an open `lockfile`, not the `SingletonLock` link, so the 1.2.1 check reads nothing there and the two apps can still both run. Reading that lock needs a Windows lane; the mechanism is inferred, not measured.
- A Dock Quit or logout that arrives while a signal's shutdown hooks run on their blocking thread gets `NSTerminateNow`, and AppKit ends the process before the hooks finish. The window is the length of the hooks. With T11's database in WAL mode the effect is a close like a crash. Not fixed in this round.
- The Dock icon during a close-quit's fetch shows the hidden window again (`RunEvent::Reopen`). Electron creates a new window then, since its `mainWindow` is null. Neither is fixed here; the root decides whether Reopen follows `handover_decision`.
- Window dragging on macOS: Electron's renderer uses `-webkit-app-region: drag`, which WKWebView ignores. The capability allows `start_dragging` and `internal_toggle_maximize`, so the Solid UI (T27/T38) needs `data-tauri-drag-region` on the title bar. WebView2 honors `app-region` on Windows.
- Windows lanes 2 and 8 need a fixture on the runner, which decision E2 keeps off GitHub.
