### SQLite build parity

- Opt level. `[profile.dev.package.libsqlite3-sys]` and `[profile.release.package.libsqlite3-sys]` set `opt-level = 3`. A 3-million-row CTE took 0.96 s to 1.12 s without the override and 0.41 s to 0.51 s with it (`sqlite-opt3.log`).
- Flags. `tauri/src-tauri/.cargo/config.toml` sets `LIBSQLITE3_FLAGS`, and `connection::open` turns on `SQLITE_DBCONFIG_DEFENSIVE`, as better-sqlite3 does for every connection. The cache size now comes from `SQLITE_DEFAULT_CACHE_SIZE`, so the pragma is gone.
- `sqlite_is_built_and_configured_as_better_sqlite3s` compares `PRAGMA compile_options` with Electron's (`electron-sqlite.json`, from `probe-sqlite.ts`). It also checks the answers those options change.
  - A double-quoted string errors with Electron's message, `no such column: "abc" - should this be a string literal in single-quotes?`, in SELECT, INSERT and CREATE INDEX.
  - The other checks are LIKE on a blob, the math functions, median and percentile, geopoly, `$name` parameters, the defensive-mode error, and `cache_size`. Without the flags it failed with 15 options missing (`sqlite-build-before.log`).
- Each better-sqlite3 option, decided:
  - Set, because they change behavior: `DQS=0`, `LIKE_DOESNT_MATCH_BLOBS`, `ENABLE_MATH_FUNCTIONS`, `ENABLE_PERCENTILE`, `ENABLE_GEOPOLY`, `DEFAULT_CACHE_SIZE=-16000`, `DEFAULT_WAL_SYNCHRONOUS=1`, `OMIT_DEPRECATED`, and `OMIT_TCL_VARIABLE`.
  - Set for compile-option parity, with no behavior change the app can see: `ENABLE_FTS4` (FTS3 already builds FTS4), `DEFAULT_MEMSTATUS=0`, `OMIT_PROGRESS_CALLBACK`, `OMIT_SHARED_CACHE`, and `TRACE_SIZE_LIMIT=32`.
  - Already in rusqlite's bundled build: `DEFAULT_FOREIGN_KEYS`, `ENABLE_COLUMN_METADATA`, `ENABLE_DBSTAT_VTAB`, `ENABLE_FTS3`, `FTS3_PARENTHESIS`, `ENABLE_FTS5`, `ENABLE_JSON1`, `ENABLE_RTREE`, `ENABLE_STAT4`, `SOUNDEX`, and `HAVE_USLEEP`.
  - Left out:
    - `ENABLE_UPDATE_DELETE_LIMIT` needs a regenerated parser, which better-sqlite3's `download.sh` builds and an amalgamation can't take. `DELETE ... LIMIT` is a syntax error in the port, and no SQL in `src/main` uses UPDATE or DELETE with LIMIT.
    - `THREADSAFE=2`: rusqlite opens every connection with `SQLITE_OPEN_NOMUTEX`, which gives the same per-connection mode.
    - `USE_URI=0`: rusqlite passes `SQLITE_OPEN_URI` per open, and every path is absolute, so none reads as a URI.
    - `ENABLE_DESERIALIZE` has been a no-op since 3.36. The `HAVE_*_T` and `HAVE_STDINT_H` defines only tell SQLite which headers exist.
  - rusqlite adds three of its own, which change nothing for correct calls: `ENABLE_API_ARMOR`, `ENABLE_LOAD_EXTENSION` and `HAVE_ISNAN`.
  - better-sqlite3 also sets `SQLITE_LIMIT_LENGTH` to V8's longest string, about 512 MiB, and `SQLITE_LIMIT_SQL_LENGTH`. Neither is ported, since both need rusqlite's `limits` feature and no row approaches them. Fix round 2 records the over-limit measurement.
- Version gap. The port bundles SQLite 3.54.1 and Electron's better-sqlite3 has 3.53.4. The only compile-option difference that comes from the version is 3.54's `MAX_SCHEMA=10000000`. T14's verifier found identical bytecode for every T14 query. Every Electron answer this unit compares (schema text, error messages, `quote()`, typed cells) matched across the gap.
- Lanes build through Tauri's CLI from `tauri/`, which runs cargo in `src-tauri`, so they read the config. A cargo run from another folder with `--manifest-path` would not, and `sqlite_is_built_and_configured_as_better_sqlite3s` would then fail.

### Handoffs the root should route

- T18, export. Electron's export is `JSON.stringify(unpackRaw(raw_gz))`. A `raw_gz` text can hold a lone surrogate escape, because V2 compresses `raw_json` as stored and Electron's `packRaw` writes lone surrogates as `\udXXX` escapes. JSON.stringify re-emits each as a lowercase `\udXXX` escape.
  - `js::parse` folds a lone surrogate to U+FFFD. So `js::stringify(js::parse(text))` prints the raw U+FFFD character instead, and two keys that differ only in their lone surrogates merge.
  - To match, an export must parse a text holding a lone surrogate escape with each lone unit mapped to a private-use character that does not occur in that text, one per unit value. It then stringifies and turns each such character back into `\u` plus the unit's four lowercase hex digits. Every other part, numbers, key order and escapes, is exact through `js::stringify`, as the fuzz shows.
  - A payload `js::parse` refuses (W5) must export `null`, as `unpackRaw` returns null.
- T12, ingest. `insert_game_full` binds through `js::bind` in `params![]`, which is right for primitives but not for an object or array `gameId`, `queueId` or `gameMode`. Electron binds those through the binder: `[5]` spreads and succeeds, and `{}` throws "Too few parameter values were provided". `js::run` gives Electron's messages.
  - `packRaw(gameData)` of a payload with a lone surrogate writes the escape in Electron and U+FFFD here, which is the export caveat above. The LCU payload should be parsed with `js::parse`, which is T19's part.
  - The duration coercion should read strings through `js::string_to_number`.
- T13. Replace the `js_number` in `db/matches.rs` with `js::string_to_number`.
- T10. The SIGTERM and SIGINT handler should end in Electron's quit path: `Database::close` (idempotent, safe from any thread), then exit 0. `RunEvent::Exit` already calls it, so `AppHandle::exit(0)` from the handler is enough.
- T08. Two restack merges: the `float_roundtrip` line, and `CommandError::named` in place of the fields `db::sqlite_error` and `db::not_open` set.
- T19. Parse every LCU response body with `js::parse`, so a truncated name with a lone surrogate reads as Electron's `JSON.parse` reads it.

## Waivers

- W1. Gzip bytes differ from Electron's. Node and Electron gzip through Chromium's zlib fork. Its deflate is not reproducible by any Rust backend: miniz_oxide, zlib-rs, and the system zlib 1.2.12 each produce different streams.
  - Measured on Electron's own V2 migration of the fixture's 669 payloads: 0 of 669 are byte-identical (`gzip-bytes.log`). The header bytes are identical. The gunzipped text is identical for every payload. Electron's total is 2,453,810 bytes and Rust's is 2,523,075 bytes, 2.8% larger.
  - Every reader of `raw_gz` gunzips it, Electron 1.2.1 included, so player data is unaffected. Byte equality would require building Chromium's zlib from source. That is the root's call.
- W2. `setSetting("auto_start")` writes the setting but does not yet register the login item. T23 owns the login item.
- W3. JavaScript coercions that Riot payloads never trigger are not ported. A non-number in a numeric field reads as its default, and a numeric string augment id is dropped. Electron carries such values to the binder. `num_or` in `payloads.rs` documents the numeric case.
  - Names. Since fix round 2, a name that is a number binds as Electron binds it. A participant name that is an array, an object or a boolean stores NULL in the port. In Electron, V2's `writeParticipants` throws `SQLite3 can only bind numbers, strings, bigints, buffers, and null` on it, `initDatabase` fails, and its recovery quarantines the file and restores the newest backup or starts empty (`electron-names-not-strings.main.log`, fix round 1). The port migrates such a file.
  - Matching the throw would make `participant_rows_from_raw` fail where T12's ingest builds on it. That is the root's call.
- W4. Log lines from migrations go to stdout and stderr until T09's `log.rs` is on the base.
- W5. Two JSON texts that JSON.parse reads are refused by serde_json, so the port reads that payload as unparseable.
  - One is a number literal that overflows a double, such as `1e400`, which JSON.parse reads as Infinity. A `serde_json::Value` cannot hold Infinity. The NonFinite arm that T08's `Js::value()` change brings is added to `db::js` by the root at the restack.
  - The other is nesting deeper than 128 levels. On the verifier's 250,000 Electron texts this was 1,420 overflow literals and 7,673 texts nested past 128, and no other differences. Depth on the export tree path goes to T18's round.
  - Riot payloads hold neither.
