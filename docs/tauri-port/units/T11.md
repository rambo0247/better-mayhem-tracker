# T11. Port the database core and prove the data opens unchanged

Branch `port/T11-db`, cut from `port/T08-contract` at `f92baba`. The tip SHA these results apply to is in the last commit that touches this file. Evidence that is not committed lives in the root checkout at `docs/tauri-port/evidence/T11/`.

## What landed

- `tauri/src-tauri/src/db/` holds `mod.rs`, `connection.rs`, `schema.rs`, `migrations.rs`, `settings.rs`, `payloads.rs`, `summoner.rs`, `filters.rs`, `stmt.rs`, and `js.rs`.
  - `js.rs` is the one addition beyond the plan's list. It holds the JavaScript semantics the port depends on: `||`, `??`, property reads that throw on `null`, `JSON.stringify`, and how better-sqlite3 binds and returns values.
- `Database::open(&data_dir, now_ms)` is managed state. Command bodies reach it through `db::of(&ctx)?.with(|conn| ...)`. It takes a data folder path, so T09's `paths.data_dir()?` passes straight in.
- `commands/settings.rs` ports `getSetting` and `setSetting` with the 10-key allow list. The `auto_start` login item side effect stays with T23.
- `lib.rs` has an interim `open_database()` that opens `$BMT_DATA_ROOT/data` only. It opens nothing when the variable is unset. The T09 rebase replaces it with `host.paths.data_dir()`. `run()` closes the database on `RunEvent::Exit`.
- `tests/db_compat.rs` and two fixtures. `electron-schema.json` is what trunk Electron created. `node-gzip.json` is a synthetic payload gzipped by Node.
- `docs/tauri-port/units/T11/electron-open.sh` opens a data root in trunk Electron through `run-electron.ts`, takes a screenshot, quits, and records the result. `compare-dbs.py` compares two databases read-only.
- Pins: `rusqlite =0.43.0` with `bundled` and `backup`, `flate2 =1.1.11` on `zlib-rs`, `jiff =1.0.2`, and `serde_json` with `preserve_order`. `bun run deps:report` reports all four as `ok`.

## Perf

- Rust, warm cache, release build, from the `open_timing_on_the_fixture` probe on the 669-game fixture over 20 runs: open and close of a current database has a median of 1.02 ms (min 0.85, max 5.53). The full V0 to V4 migration has a median of 1465 ms (`open-timing.log`).
- The plan's metric needs Electron's median and a cold page cache. Clearing the page cache takes `purge`, which needs sudo, and the rules forbid sudo. Electron's `initDatabase` cannot be timed without instrumenting `src/`. Both are left to the perf lane and reported to the root as a waiver.

## Waivers

- W1. Gzip bytes differ from Electron's. Node and Electron gzip through Chromium's zlib fork. Its deflate is not reproducible by any Rust backend: miniz_oxide, zlib-rs, and the system zlib 1.2.12 each produce different streams.
  - Measured on Electron's own V2 migration of the fixture's 669 payloads: 0 of 669 are byte-identical (`gzip-bytes.log`). The header bytes are identical. The gunzipped text is identical for every payload. Electron's total is 2,453,810 bytes and Rust's is 2,523,075 bytes, 2.8% larger.
  - Every reader of `raw_gz` gunzips it, Electron 1.2.1 included, so player data is unaffected. Byte equality would require building Chromium's zlib from source. That is the root's call.
- W2. `setSetting("auto_start")` writes the setting but does not yet register the login item. T23 owns the login item.
- W3. JavaScript coercions that Riot payloads never trigger are not ported. A non-number in a numeric field reads as its default, and a numeric string augment id is dropped. Electron would carry such values through. `num_or` in `payloads.rs` documents the numeric case.
- W4. Log lines from migrations go to stdout and stderr until T09's `log.rs` is on the base.
