## Fix round 1

- `score_badge`. T08's contract types it `ScoreBadge | null` (`tauri/src/bindings.ts`: `score_badge: ScoreBadge | null`, `ScoreBadge` is `"MVP" | "ACE"`), so text other than MVP or ACE reads as `null`, as T15 and T16 do. Electron passes the text through, and the renderer only compares it with the two names. The `FromSql for ScoreBadge` impl is gone; `MatchListItem` and `PlayerStatsRecord` read the column through `badge()`, which also removes the sibling-impl conflict the round 0 waiver named. A non-text value (`7`) reads as null too.
- Patch order. `patch_part` is now `Number(text)` (`js_number`): whitespace trim (JavaScript's set, so U+0085 does not trim), blank is 0, `0x`, `0o`, `0b`, `Infinity`, plain decimals, and NaN for everything else (`inf`, `nan`, `1_6`, a sign inside a radix literal). T11's `db::js` has no string to number function, and `filters::js_number` there takes `inf` and `+` inside a radix literal, so `js_number` lives in `db/matches.rs`; the root may lift it into `db::js`. The sort is V8's own for fewer than 64 patches (one run found from the front, then binary insertion), because a NaN makes the comparator inconsistent and any other stable sort orders those patches differently. At 64 patches or more the same binary insertion runs, which equals V8's order whenever the comparator is consistent.
- `LOCAL_SESSION_DATE` is `local_session_date()`, built from `filters::DAY_START_HOUR`. A test pins the SQL text byte for byte.
- The tools moved from `docs/tauri-port/units/T13/` to `parity/t13/`: `record-matrix.ts`, `perf-match-history.ts`, `week-data.js`, `week-rs.js`, and the new `patch-probe.ts`. Imports point at `../run-electron.ts` and `../run-tauri.ts`. One lint finding (`no-useless-assignment` in `record-matrix.ts`) is fixed. `bun run lint`, `bun run fmt:check` and `bun test` pass in `parity/`.

Each fix has a test that fails on the old code (run against `5228014` with the new tests pasted in): `patches_with_numeric_text_sort_as_javascript_sorts_them` (`["15.9","0x10.1"]` came out in the wrong order), `patches_that_are_not_numbers_keep_the_order_javascript_gives_them` and `a_score_badge_other_than_mvp_or_ace_reads_as_none` (panicked on `InvalidType`) fail there. `number_reads_text_as_javascript_does` and `session_dates_cut_the_day_at_the_day_start_hour` pin the new code. Expected patch orders come from `Array.prototype.sort` in Node with the dropdown's comparator.

The verifier's patch probe replays on trunk Electron through `parity/t13/patch-probe.ts` (the 16 odd versions on the 16 newest games of a fixture copy): Electron's 31 patches match the Rust order exactly, in `patch_probe` (`BMT_T13_PATCH_PROBE`, `BMT_GOLDEN_DATA`).

## Waivers and open points

- `firstDayOfWeek` needs the system locale, which T09's `locale::system_locale` provides. T09 is not in this branch's ancestry, so `commands::matches::system_locale` returns `None` until the root rebases onto T09; then it should call `crate::locale::system_locale()`. Week start is Sunday until T09's locale is stacked below this branch. With `None` the week opens where the default locale's does, as `firstDayOfWeek(undefined)` does in Electron: Sunday, for `en-US`.
- A game with no `player_stats` row makes `getMatchDetail` throw a `SqliteError` where Electron returns `stats: undefined`. Ingest writes both rows together, so only a damaged file reaches it, and `MatchDetail` from T08 has no way to say `undefined`. Waived.
- Hostile mistyped arguments (a string or float game id, a missing argument, a number for a patch) are rejected by the T08 command layer where Electron coerces them. That is T08 contract item 6, not this unit's query code.
- `golden.rs` replays T05's `state` goldens (group `state`, `seq` 1000000) on the plain fixture, and 7 of them fail for these channels (`match-sessions` 3, `profile` 1, `settings:get` 3): they record pages whose state seeded its own data or settings, for example `match-history-empty-waiting`, whose `db:profile` is `{name: null}`. They arrived with T05's later re-record and are the root's call; every `read` and `write` case still passes.
- `js_number` folds a radix literal's digits as doubles, so a hex literal past 2^53 may differ from JavaScript in its last bit. No game version string reaches that, and no test covers it.
- `tests/golden.rs` parses goldens with serde_json's default float parser, which can miss the nearest double by an ulp. Its replay passed here, but a bit-exact float check needs serde_json's `float_roundtrip` feature, which is the root's call on `Cargo.toml`.
- Time zone. `firstDayOfWeek` and `db/week.rs` do not read a zone. The first push failed CI on the `en-UK` probe, not on a zone: Electron canonicalizes deprecated regions, and the next commit added those aliases. The lib tests pass under `TZ=UTC`, `TZ=Asia/Tokyo` and `TZ=America/New_York`. Session keys use Electron's SQL text, `'localtime'`, so SQLite reads the process zone, just as it does in Electron's main process. Season windows come from T11's `filters.rs`, which uses `TimeZone::system()`. `electron_matrix` and `fixture_goldens` need `TZ=America/New_York`, the zone the recording ran in, and skip without their env vars. Pinning the zone explicitly would mean changing the SQL text or T11's filters, so that is the root's call along with T08's fix round.
- `/deslop` and `/no-comments` are not installed. Their rules were applied by hand.
