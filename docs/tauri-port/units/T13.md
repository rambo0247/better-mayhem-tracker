# T13. Port the match queries

Branch `port/T13-match-queries`, cut from `origin/port/T12-scoring` at `9909f86`. No GitHub pull request exists for the branch. The tip SHA these results apply to is in the owner's code-ready report; the record changes only with code.

## What changed

- `tauri/src-tauri/src/db/matches.rs` ports `src/main/db/matches.ts`: `getMatchHistory`, `getMatchSessions`, `getMatchFilterOptions`, `getMatchDetail`, `toggleFavorite`, and `getChampionMatchHistory`. The SQL is Electron's text, whitespace included, with the hidden-queue, remake and season filters from T11's `db/filters.rs`. Rows are read through `stmt.rs` by index, never by name per row. The spike's `db.rs` query from `d3f2ed0` is superseded by `getMatchHistory` here; nothing of it survives that the TypeScript does not also say.
- `tauri/src-tauri/src/commands/matches.rs` fills the 9 command bodies. `db:stored-queues`, `db:profile` and `db:all-summoner-puuids` call the T11 helpers (`filters::get_stored_queues`, `summoner::get_profile`, `summoner::get_all_puuids`) that already held those queries.
- `tauri/src-tauri/src/db/week.rs` and the generated `db/week_data.rs` port `firstDayOfWeek`, which week sessions need. JavaScript resolves the locale against the ICU data Electron ships, then reads the resolved locale's region. Electron's ICU holds 372 locales with a region where Node's holds 663, so the table comes from Electron itself: `docs/tauri-port/units/T13/week-data.js` collects it in Electron's main process and `week-rs.js` writes the Rust.
- `tauri/src-tauri/src/db/mod.rs` gains the three module lines. That file is T11's; the lines are the only change.

## Tools, all rerunnable

- `docs/tauri-port/units/T13/record-matrix.ts` launches trunk Electron through `parity/run-electron.ts` on fixture copies and calls `window.api` for 7,684 cases over two data variants (3,827 and 3,857). Variant `fixture` is the anonymized fixture. Variant `accounts` adds a second account with no summoner row, games with an empty puuid, a summoner with no icon or tag, null and empty patches, and more favorites, so the fallbacks the fixture never reaches run too. Fractional numbers are written as their f64 bits: the devtools protocol prints a returned double with too few digits, and serde_json parses decimals only to within an ulp, and both moved values off their last bit until the recorder carried them as JSON text and bits.
- The `electron_matrix` test in `db/matches.rs` replays that recording against the Rust queries on the same fixture copies and compares every value, floats by their bits.
- `docs/tauri-port/units/T13/perf-match-history.ts` is the perf probe below.

## Unit boxes

- [x] `db/matches.rs` tests run each query on the fixture with each filter and sort and assert row counts and the first and last row against the goldens. `fixture_goldens` does exactly that for the 33 read-group goldens of these channels. `electron_matrix` goes further and compares whole results for 7,684 cases. Both need the gitignored fixture and goldens (`BMT_GOLDEN_DATA`, `BMT_GOLDEN_DIR`, `BMT_T13_MATRIX`) and skip with a message in CI. Five synthetic tests on an in-memory database run everywhere: unscored games sort last both ways, filters and paging, remakes count only as games in sessions, patch order, and favorites.

### Perf

Not measured by the owner. The probe needs a Tauri window, and `wait-screen.sh` held it for over 10 minutes because the screen was locked, so the owner stopped it rather than wait. ## Waivers and open points

- `firstDayOfWeek` needs the system locale, which T09's `locale::system_locale` provides. T09 is not in this branch's ancestry, so `commands::matches::system_locale` returns `None` until the root rebases onto T09; then it should call `crate::locale::system_locale()`. With `None` the week opens where the default locale's does, as `firstDayOfWeek(undefined)` does in Electron: Sunday, for `en-US`.
- `impl FromSql for ScoreBadge` lives in `db/matches.rs`. T14 to T16 read `score_badge` too; if a sibling adds its own impl, the chain will not compile until one is removed.
- A game with no `player_stats` row makes `getMatchDetail` throw a `SqliteError` where Electron returns `stats: undefined`. Ingest writes both rows together, so only a damaged file reaches it, and `MatchDetail` from T08 has no way to say `undefined`.
- `tests/golden.rs` parses goldens with serde_json's default float parser, which can miss the nearest double by an ulp. Its replay passed here, but a bit-exact float check needs serde_json's `float_roundtrip` feature, which is the root's call on `Cargo.toml`.
- Time zone. `firstDayOfWeek` and `db/week.rs` do not read a zone. The first push failed CI on the `en-UK` probe, not on a zone: Electron canonicalizes deprecated regions, and the next commit added those aliases. The lib tests pass under `TZ=UTC`, `TZ=Asia/Tokyo` and `TZ=America/New_York`. Session keys use Electron's SQL text, `'localtime'`, so SQLite reads the process zone, just as it does in Electron's main process. Season windows come from T11's `filters.rs`, which uses `TimeZone::system()`. `electron_matrix` and `fixture_goldens` need `TZ=America/New_York`, the zone the recording ran in, and skip without their env vars. Pinning the zone explicitly would mean changing the SQL text or T11's filters, so that is the root's call along with T08's fix round.
- `/deslop` and `/no-comments` are not installed. Their rules were applied by hand.
