## Fix round 1

- A REAL in an INTEGER column. SQLite keeps a value that is not whole as a REAL whatever the column's affinity, so `games.game_duration = 1500.25` makes `SUM(g.game_duration)` a REAL. Electron returns it (the root's example reads `totalDuration: 711290.25`), and the port failed with `InvalidColumnType(1, "totalDuration", Real)`, which I reproduced on `b5dd5b6`. `db/num.rs` adds `Num`, one double that reads an INTEGER or a REAL, prints as TypeScript `number` (so `bindings.ts` is unchanged and `export_bindings --check` reports it fresh) and serializes a whole value as an integer, so a column that holds only integers answers exactly as before. Fields that come from a `SUM`, `MIN`, or a per-game column are `Num` in `commands/stats.rs` (champion, augment, dashboard, global, trends, recent form), in `CareerRow`, and in the shared `AugmentStats`, `ItemStats`, `Multikills` and `RecordMatchRef` in `commands/types.rs`. `compute_records` reads them as doubles, as the JavaScript does: KDA, `Math.max(deaths, 1)`, the truthiness of `win` and the streak walk's `run.win !== r.win`. Counts (`COUNT`), ids, `game_creation` and the `CAST ... AS INTEGER` hour and weekday stay `i64`.
- The bit-exact harness no longer skips a missing channel folder. `read_cases` panics when any of the nine channels' folders cannot be read or is empty (`a_missing_channel_folder_fails_the_replay` and `an_empty_channel_folder_fails_the_replay` fail on the old harness, which `continue`d). It also drops T05's `state` goldens, 9 of them now that T05 re-recorded the states: they answer pages seeded with their own games (`match-history-empty-waiting` answers `getDashboard` with no games), so on the fixture 5 differ by construction. The count is printed.
- Perf numbers are refreshed from T05's current `parity/out/golden/timing.json` and the live lane ran.

Tests that fail on the old code: `fraction_tests::the_dashboard_sums_fractions_as_javascript_does` (on `b5dd5b6` with the test pasted in: `InvalidColumnType(1, "totalDuration", Real)`), and the three tests of `fraction_tests` for champion stats, trends and records, which need `Num`.

## Notes for the root

- Round 1 changed shared types. `commands/types.rs` holds `AugmentStats`, `ItemStats`, `Multikills` and `RecordMatchRef` with `Num` where `i64` stood, and `CareerRow` fields are `Num`. T15's and T16's code that builds or reads those (T16's recap reads `CareerRow`'s kills, wins, duration and damage fields) needs `.0` or `Num::from` when the root restacks. `bindings.ts` does not change.
- Still `i64`, so a REAL there still errors: `game_id`, `game_creation` and `queue_id` of a game, `champion_id`, `augment_id`, `item_id`, and `COUNT` results. The hostile recording does not touch them. Electron returns such a value too, so this is a gap, not a match.
- `golden.rs` replays T05's `state` goldens on the plain fixture. For these channels 5 fail by construction; the root's call, as for T13.

- `golden.rs` compares floats after `serde_json`'s default parse, so a one-ulp difference can read `pass`. Enabling `serde_json`'s `float_roundtrip` feature in `Cargo.toml` (T08's file) would make every unit's replay exact. This unit adds its own bit-exact check instead.
- `db/stats.rs` implements `FromRow` for the shared `AugmentStats` and `ItemStats` from `commands/types.rs`. A sibling unit that adds its own impl for either (T16's season top items read `ItemStats`) will not compile beside this one. T16 should reuse these, along with the public `career_rows`, `career_where`, `compute_records`, `match_of`, `higher`, `lower`, `item_slot_union`, `ITEM_SLOTS`, and `excluded_items_sql`.
- Electron's `getAugmentStats` tests `championId !== undefined`, so a renderer passing `null` would get zero rows. A Tauri `Option` cannot tell `null` from absent. The renderer only passes a number, and T05 records `undefined` arguments as `null`, whose goldens expect rows, so the port treats `null` as absent.
- better-sqlite3 bundles SQLite 3.53.4 and rusqlite 0.43 bundles 3.54.1. Row order on ties and every float still match across the whole matrix.
- Trends and season windows read local time. The goldens were recorded under `TZ=America/New_York`, so the replays run under that zone.
