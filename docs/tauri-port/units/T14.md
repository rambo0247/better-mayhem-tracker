## Verify, perf

The plan's rule is that Tauri's median may exceed Electron's by at most 25% or 2 ms, whichever is larger. The baseline is T05's `timing.json` (renderer round trip, 50 calls).

The Rust side here is a ballpark, not the live lane. A throwaway test, deleted after the run, called each command 50 times through Tauri's mock IPC in a release build without LTO, 7 runs, on a machine at load average 24 on 10 cores. It times the command, its SQL, and JSON serialization, but not the webview transport.

| Channel, case | Electron median | Rust median of 7 runs (range) |
| --- | --- | --- |
| db:global-stats default | 15.7 ms | 15.49 ms (15.25 to 15.70) |
| db:global-stats patch | 13.8 ms | 12.97 ms (12.80 to 13.59) |
| db:global-stats queue | 22.6 ms | 22.41 ms (21.88 to 26.27) |
| db:trends default | 2.6 ms | 2.06 ms (2.02 to 2.34) |
| db:trends queue | 2.7 ms | 2.38 ms (2.23 to 2.66) |

Both channels are bound by SQLite running the same SQL. The queue case is slower than the default in both apps by the same margin, which points at the query plan and not at either runtime. Every case is inside the rule on this probe. The live perf lane, renderer round trips alternating apps every 10 calls, is still open for the swarm.

## Notes for the root

- `golden.rs` compares floats after `serde_json`'s default parse, so a one-ulp difference can read `pass`. Enabling `serde_json`'s `float_roundtrip` feature in `Cargo.toml` (T08's file) would make every unit's replay exact. This unit adds its own bit-exact check instead.
- `db/stats.rs` implements `FromRow` for the shared `AugmentStats` and `ItemStats` from `commands/types.rs`. A sibling unit that adds its own impl for either (T16's season top items read `ItemStats`) will not compile beside this one. T16 should reuse these, along with the public `career_rows`, `career_where`, `compute_records`, `match_of`, `higher`, `lower`, `item_slot_union`, `ITEM_SLOTS`, and `excluded_items_sql`.
- Electron's `getAugmentStats` tests `championId !== undefined`, so a renderer passing `null` would get zero rows. A Tauri `Option` cannot tell `null` from absent. The renderer only passes a number, and T05 records `undefined` arguments as `null`, whose goldens expect rows, so the port treats `null` as absent.
- better-sqlite3 bundles SQLite 3.53.4 and rusqlite 0.43 bundles 3.54.1. Row order on ties and every float still match across the whole matrix.
- Trends and season windows read local time. The goldens were recorded under `TZ=America/New_York`, so the replays run under that zone.
