## Build

- [x] `db:teammate-stats`, `db:teammate-groups`, `db:teammate-detail`, and `db:teammate-group-detail` are ported. Rows come back newest first. Players and groups come back in JavaScript `Map` insertion order (`JsMap`), including the delete and re-set when a name-keyed player moves under a puuid. The sorts are the same stable sorts Electron uses.
- [x] Group keys come from rosters ordered by games, with ties broken by `crate::intl::locale_compare`, which is ICU4X's root collator at default options. It agrees with Electron's `localeCompare` on all 8,742 recorded pairs (ASCII, accented Latin, emoji, CJK, NFD-equal) through `BMT_COLLATION_CASES=<tsv of a, b, -1|0|1>`.
- [x] Teammate keys are puuids, or `Name#TAG` when a row has no puuid. The backend takes the raw key. A tag line that contains `#` round-trips through stats and detail.

When T22 ports Data Dragon, it should hand these commands its in-memory classes and wait the way `waitForChampionData` does. On a fresh install with no cache, teammate scores use the default weights until then.
- `db::teammates::CareerFilter` mirrors `records.ts`. If T14 defines its own, merge the two. T16's season recap calls `get_teammate_stats(conn, &filter, MIN_SHARED_GAMES)`.
- `MATCH_ROW_SQL` and a `FromRow` for match rows (a private `MatchRow` newtype) live in `teammates.rs`. The newtype means T13's own impl can't conflict. Once T13 lands, the copy can move to `db/matches.rs`.

T16's `icu_decimal` formatting joins it as `intl::format_integer(n, locale: Option<&str>)` with the same `Option<&str>` shape.
- At the restack onto T14, `CareerFilter` in `db/teammates.rs` has the same four fields as `db::records::CareerFilter`. Replace the struct (lines 36 to 43) with the one line `pub use super::records::CareerFilter;`. Nothing else changes.

## Collation, round 1

- **Size.** Release `better-mayhem-tracker-tauri`, strip and LTO as configured: 5,713,952 bytes before, 6,903,696 after (+1,189,744, +20.8%). Measured at 6252e89 and the fix on the same target dir.
- **ICU4X data.** `icu_collator` 2.4.0 ships CLDR 49.0.0 and Unicode 18.0.0. Electron 44 has ICU 78.2 and CLDR 48. The gap is one CLDR release. It is a guess that it can reorder anything outside the 8,742 pairs, none did there. T39 and T40 should re-record the pairs when Electron's ICU moves.
- **deps:report.** Both crates `ok`. The two rule breaks it lists (typescript and one more npm package) are not from this unit.
- **Electron's default locale** (Electron from this repo's node_modules, a no-window main-process probe, `env -i`, temp userData). `LANG` unset: en-US, `'aa'.localeCompare('b')` is -1. `LANG=en_US.UTF-8` and `LANG=C`: en-US. `LANG=da_DK.UTF-8`, with or without `LC_ALL`: collator and date locale da-DK, and `'aa'.localeCompare('b')` is 1, while `app.getLocale()` stays en-US. The verifier's `--lang=da` and AppleLanguages runs stayed en-US. So a Finder launch, where `LANG` is unset, collates as root. Tauri uses root. A terminal launch under a non-English `LANG` differs in Electron and not here. That is a waiver: no packaged user launches that way.
- **Windows.** Not probed. `src/main/locale.ts` says the packaged app ships en-US strings only, so Chromium's app locale is en-US whatever the display language. That points to root there too, but ICU on Windows can take its default from the user locale, so it is a guess. T39 should run the same probe on windows-latest: `Intl.Collator().resolvedOptions().locale`, `'aa'.localeCompare('b')` and `'e'.localeCompare('\u00e9')`, once at the runner default and once after `Set-Culture da-DK`. If the second run gives da-DK, `intl::collator` needs the Windows user locale from T09's `locale.rs`.
- **Other `localeCompare` and `Intl` uses on trunk.** In `src/main/`: only `db/teammates.ts:240` calls `localeCompare` (T15, done). There is no `Intl.Collator`. `db/recap.ts:229` uses `toLocaleString(locale)` and `shared/text.ts` `ordinal` (T16, numbers, via `icu_decimal`), and `locale.ts` uses `Intl.getCanonicalLocales` (T09). The renderer calls `localeCompare` in `Augments.tsx:92` (T28), `Challenges.tsx:195` (T30), `GlobalChampionDetail.tsx:121` and `GlobalStats.tsx:133,171,197` (T33), and `MatchHistory.tsx:468` (T37). Those run in the webview's own ICU, not Rust, so the owners need no call to `intl`, but WKWebView and WebView2 collate with their system ICU, which T27 and T40 should keep in mind.

## score_badge

Electron's row reader hands back whatever string is in `player_stats.score_badge`. T15 reads `MVP` and `ACE` and gives null for anything else. It can't pass other strings through, because `ScoreBadge` in `commands/types.rs` is a closed enum shared with T13, T14 and T16, and that file is outside this unit. The app writes only `MVP`, `ACE` or NULL (scoring and ingest), so it matters only for a hand-edited database. T13's `FromSql for ScoreBadge` errors on the same input, which differs from both. For the root: decide once whether to add an `Other(String)` carrier with hand-written serde to `ScoreBadge`, and have T13, T14, T15 and T16 use it.
