# T15. Port the teammate and group queries

Branch `port/T15-teammates`, from `origin/port/T12-scoring` at 9909f86. The evidence below applies to the code commit 506da99. This record is the only change after it.

## Files

- `tauri/src-tauri/src/db/teammates.rs` is new. It ports `src/main/db/teammates.ts`.
- `tauri/src-tauri/src/commands/teammates.rs` fills in the four command bodies.
- `tauri/src-tauri/src/db/mod.rs` gets one line, `pub mod teammates;`. The module can't compile without it.

## Build

- [x] `db:teammate-stats`, `db:teammate-groups`, `db:teammate-detail`, and `db:teammate-group-detail` are ported. Rows come back newest first. Players and groups come back in JavaScript `Map` insertion order (`JsMap`), including the delete and re-set when a name-keyed player moves under a puuid. The sorts are the same stable sorts Electron uses.
- [x] Group keys come from rosters ordered by games, with ties broken by `localeCompare`. `locale_compare` reproduces ICU's root order for ASCII: punctuation, then digits, then letters, with case only as a tertiary level. Node's `localeCompare` and the Rust code agree on 20,000 random ASCII pairs (`BMT_COLLATION_CASES` runs the check).
- [x] Teammate keys are puuids, or `Name#TAG` when a row has no puuid. The backend takes the raw key. A tag line that contains `#` round-trips through stats and detail.

## Verify, unit

- [x] Golden replay against T05's goldens passes all 4 channels. That covers default and `set-3` for stats and groups, plus a hit and a miss for both details.
- [x] Fixture comparison against trunk Electron. Electron built from this worktree's `src/` (trunk) answered 828 calls on fresh fixture copies. Those answers were written as T05-format goldens and replayed through `tests/golden.rs`, and every case passes.
  - Stats and groups for no season, `set-0` to `set-3`, and an unknown set.
  - Detail for all 532 teammates, and group detail for all 237 groups. Groups in the fixture have 1 to 4 friends, so up to 5 players with us.
  - Misses: an unknown key, the empty key, an upper-cased puuid, and a group key with an extra member.
  - `hidden_queues` set to `2450` (no effect), to `2400` (every game hidden), and to ` 2400 ,abc,2450`. Each run covers stats, groups, and details.
  - Seam logs show 0 blocked writes.
- [x] `db/teammates.rs` unit tests cover these cases.
  - A `#` key round-trips.
  - A name-keyed player merges into a puuid.
  - An older name-only row stays separate in the list but joins the detail.
  - A group member needs 3 games.
  - Roster order and the group key are checked.
  - A season filter selects games without changing who counts as a friend.
  - ICU collation cases are checked.
  - Champion classes are read from the cache file.

## For the root

- Champion classes come from `champion-cache.json` beside `matches.db` (`cached_champion_classes`). That is the file Electron hydrates at startup. When T22 ports Data Dragon, it should hand these commands its in-memory classes and wait the way `waitForChampionData` does. On a fresh install with no cache, teammate scores use the default weights until then.
- `db::teammates::CareerFilter` mirrors `records.ts`. If T14 defines its own, merge the two. T16's season recap calls `get_teammate_stats(conn, &filter, MIN_SHARED_GAMES)`.
- `MATCH_ROW_SQL` and a `FromRow` for match rows (a private `MatchRow` newtype) live in `teammates.rs`. The newtype means T13's own impl can't conflict. Once T13 lands, the copy can move to `db/matches.rs`.
- `locale_compare` sorts non-ASCII characters by code point after ASCII. ICU orders them differently, so a group whose tied members include a non-ASCII name-only key can order differently from Electron. Puuids are ASCII.
