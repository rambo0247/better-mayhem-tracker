# T16. Port the recap, card, and season queries

Branch `port/T16-recap`, from `origin/port/T12-scoring` at 9909f86. The code commit 2c77bd0 holds the port. Later commits make one season test independent of the zone, move the T14 and T15 copies under those units' names, and fix `MIN_SHARED_GAMES`. ## What changed

`db:game-recap`, `db:game-card`, `db:season-recap`, and `db:seasons` answer from Rust. Before this unit they answered "not ported".

- `tauri/src-tauri/src/db/recap.rs` ports `recap.ts`. It also holds `getMatchDetail` and `getGameMapName` and `getGameProfileIcon` from `live.ts`, plus `getGameChallenges` from `challenges.ts`.
- `tauri/src-tauri/src/db/season.rs` ports `season.ts`.
- `db/records.rs`, `db/stats.rs`, and `db/teammates.rs` hold this unit's copies of what the season recap reads from T14 and T15. They use T14's and T15's file and function names, so a restack takes their side of each file whole. `records.rs` has `CareerRow`, `CareerFilter`, `career_where`, `career_rows`, `compute_records`, `match_of`, `higher`, and `lower`. `stats.rs` has `excluded_items_sql`, `ITEM_SLOTS`, and `item_slot_union`. `teammates.rs` has `get_teammate_stats(conn, &filter, min_games)` and `MIN_SHARED_GAMES`. None of them implements `FromRow` for `AugmentStats` or `ItemStats`. `season.rs` reads those through private row types.
- `tauri/src-tauri/src/session.rs` ports `sessionDay` and `addDays`, plus the local hour and weekday, using jiff.
- `tauri/src-tauri/src/text.rs` ports `ordinal`, plus integer `toLocaleString` for the milestone labels.
- `commands/recap.rs` fills in the four command bodies. `db/mod.rs` and `lib.rs` register the modules.

### How the Electron comparison ran

These scripts are scratch tools, outside the repo, because no file of this unit's section holds parity tooling.

1. Trunk was an APFS clone of the root app's sources (`src/` identical to this branch). Its `out/` came from my own `npm run build`. T05's parity tooling supplied `run-electron.ts` and the seam preload.
2. `cmp-t16.ts` launched trunk Electron through `startElectron` on a copy of `port-T02-baseline/parity/snapshots/fixture`. It went through `wait-no-game.sh` and `capture-slot.sh`. For each case it called `__bmtRawInvoke` and read the handler's result from the seam's `end` record.
3. An ignored Rust test ran the same cases on a copy of the same database, with the clock frozen at `2026-11-23T02:00Z` and `TZ=America/New_York`.
4. `compare.py` walked both outputs and compared every number by its `struct.pack(">d")` bytes.

## Verify, perf

The plan's metric is the `db:season-recap` round trip on the largest season. T05's `timing.json` has no case for set-2, the largest season with 301 games, or for all time. It has the default case (set-3, 160 games) at a 7.0 ms median and set-1 (88 games) at 3.5 ms.

The in-process Rust time (release, the app's own connection and schema init, 50 calls each, `nice -n 10`) breaks down like this:

| case              | Electron median round trip (T05) | Rust median, in process |
| ----------------- | -------------------------------- | ----------------------- |
| default (set-3)   | 7.0 ms                           | 5.4 ms                  |
| set-1             | 3.5 ms                           | 2.2 ms                  |
| set-2             |                                  | 5.2 ms                  |
| all               |                                  | 14.0 ms                 |

The time goes to SQL. In order, the slowest parts are team shares, then the item union, then teammates, then augments. A first run on a bare `Connection::open` measured twice as slow, because it skipped the app's `cache_size` pragma. That number is not the app's.

The live round-trip run alternates apps every 10 calls, 50 calls each, for set-2 and all. The Tauri binary is a `--features parity-driver` build at `CARGO_PROFILE_DEV_OPT_LEVEL=3`, because a plain debug build compiles SQLite at `-O0`. That run never started. `wait-screen.sh` held it for over 20 minutes because the screen was locked, and I stopped it when the root asked for an early report. The perf box stays open. `perf-t16.ts` and the optimized binary are in the owner's scratchpad, ready to rerun.

## Waivers and notes for the root

- **Duplicated pieces.** When T14 and T15 land below this unit, take their `db/records.rs`, `db/stats.rs`, and `db/teammates.rs` whole. Two things the root must reconcile:
  - T15 defines its own `CareerFilter` in `teammates.rs`, while this unit and T14 use `records::CareerFilter`. One of the two has to go.
  - `match_detail` in `recap.rs` still duplicates T13's `getMatchDetail`.
- **Fixed after the first report.** `MIN_SHARED_GAMES` is 2 in `api.ts`. The first head used 3. The fixture comparison could not see the difference, because no friend in any recap's top five has exactly 2 shared games. A test in `db::teammates` now covers 2 shared games and the account filter.
- **No `seasons.rs`.** `SEASONS`, `find_season`, and `season_bounds` already live in T11's `db/filters.rs`, so I did not create it. `ALL_TIME_ID` lives in `db/season.rs`.
- **Locale.** The commands pass no locale, which formats as en-US. T09's `locale::system_locale()` is not on this base. Once it lands, `get_game_recap` should receive `locale::system_locale().as_deref()`. `text.rs` groups digits from a CLDR table of common locales. Only en-US is checked against Electron.
- **Time zone.** The session days follow `TimeZone::system()`. The replay and the comparison need `TZ=America/New_York`, the zone the goldens were recorded in.
- **Golden data drift.** The goldens' manifest records `dbSha256` 32f91f0a…. T05's `parity/snapshots/fixture` now holds e410b895…, the same file as T02's fixture. In that file challenge 101203 is named "KeenThistle4 Day". The goldens still say "Snow Day". Replay on either copy therefore fails `db:game-recap default` on that one name, and every other field matches. On the 32f9 copy, before it was replaced, the replay passed all 13 cases. The Electron comparison on e410 matches 1442 out of 1442. The goldens need re-recording on the current fixture, or the 32f9 database restored.
- **Champion data wait.** Electron's `getGameRecap` and `getGameCard` handlers wait for `dragon.waitForChampionData()`. No query here reads champion data, so the commands don't wait. That wait belongs to T22.
- **A game with no `player_stats` row.** `MatchDetail.stats` cannot be absent in T08's types. Such a game returns a SQLite "no rows" error where Electron would send the detail without `stats`. Ingest writes both rows in one transaction, so the case should not occur.
- **Live lanes.** The ten live lanes are the verdict swarm's.
