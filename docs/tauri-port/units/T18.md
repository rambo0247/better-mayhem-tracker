## Build

- [x] `data:export` shows the save dialog with Electron's title `Export Better Mayhem Tracker Data`, default name `better-mayhem-backup-<UTC date>.json` and the `JSON` filter, parented to the calling window. Cancel answers `{ success: false }`. The file is `{"version":3,"summoners":<SELECT * FROM summoner>,"games":[...]}`. Games are paged 200 at a time by `game_id`, each payload gunzipped, given `_ownerPuuid`, and stringified as `JSON.stringify` does, with the database free between pages. A failure removes the partial file and answers `Export failed: <message>`, with Node's `fs` message form (`ENOENT: no such file or directory, open '<path>'`).
- [x] `data:import` shows the open dialog with Electron's title, filter and `openFile`. The scanner is a byte-for-byte port of `BackupScanner`, quirks included: a trailing comma passes, a key that is not a string is kept apart from string keys, JavaScript's `trim()` and `/\s/` whitespace (BOM, NBSP) is accepted where Electron accepts it. The file is read in 64 KiB chunks, decoded as Node's UTF-8 stream decodes (U+FFFD for an invalid sequence, a sequence cut by a read carried over), because a batch flushes, and so a progress event goes out, only at a chunk edge. Two passes, the pre-import backup between them, accounts upserted in one transaction, then games 50 per `js::transaction` batch with `data:import-progress` after each flush and `lcu:games-updated` every 100 new games and at the end. `Number(version)` follows ECMA-262. Errors map as Electron's handler maps them: any `SyntaxError` is `it isn't valid JSON`, anything else its message, `summoners.filter is not a function` included. One import at a time.
- [x] `data:repair-puuids` takes the `pre-repair` backup, then runs `repairPuuids` in one locked call, over `IndexMap` and `IndexSet`, as JavaScript's `Map` and `Set` iterate in insertion order. That order decides which account takes a game and the order rows are written in, which a dump shows.
- [x] Champion classes and their version come from `champion-cache.json` beside `matches.db`, which is what Electron hydrates from disk at startup and what it has once its network load fails. T22 replaces this with the loaded Data Dragon state and `waitForChampionData`.

### Deviations, each with its reason

- raw_gz is compared by its gunzipped content, not its bytes. Electron's main process links Chromium's zlib fork, which deflates differently. That is T11's waiver W1, accepted by the root. The export file does not embed raw_gz, so it is byte-identical.
- A payload holding a lone UTF-16 surrogate escape (`"\ud800"`) fails serde_json's parse. JSON.parse accepts it. On export such a game is skipped, on import it counts as unreadable. Riot payloads hold none.
- `node_error` maps `io::ErrorKind` to the libuv code and text. Kinds outside the table read `UNKNOWN: unknown error`.

## Perf

Method. Each pair runs trunk Electron and then the Tauri commands on a fresh fixture copy: the export of the 669-game fixture, and the import of T05's export (20.97 MB) into the emptied library. Electron's time is its main process's handler time from the seam's start and end records. Tauri's is the IPC round trip through `tauri::test::get_ipc_response` in the LTO release test binary, the same command bodies the app runs. Both include the dialog seam; the import includes the pre-import backup in both. `perf.sh` starts each pair only once the 1-minute load average is below 10.

Rerun, one pair per call, from `parity/out/t18`: `./perf.sh`, which waits for a 1-minute load below 10 (2 h cap) and then runs `capture-slot.sh bun probe.ts perf <export-fixture|import-emptied> <run>`, appending to `perf2.log`.
