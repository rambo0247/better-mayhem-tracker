## Build

- [x] `tls.rs`. rustls 0.23.46 with the `ring` provider passed explicitly (`builder_with_provider`, never installed as the process default) and `with_webpki_verifier` over a `RootCertStore` holding only `RIOT_ROOT_CA`. Hostname checks stay on. No custom verifier and no `dangerous()` anywhere in `src/lcu/`. HTTP offers ALPN `http/1.1`. The socket offers none, so it cannot negotiate `h2`. `RIOT_ROOT_CA` is byte-identical to `src/main/lockfile.ts` (text diff) and to the prototype's `riot_root.pem` (same SHA-256 of the DER).
- [x] `reqwest` 0.13.5 with `rustls-no-provider` and `use_preconfigured_tls`, `http1_only`, `no_proxy`, and no redirects followed, as Node's `https.request` behaves. `tokio-tungstenite` 0.30.0 with `Connector::Rustls` over the same roots. `Cargo.lock` holds no `native-tls`, `openssl`, or `aws-lc-rs`.
- [x] `lockfile.rs` ports `lockfile.ts`: Electron's exact lockfile regex (a password may hold `:`), the reported folder first, then the Riot Client's records in name order (as libuv's `readdirSync` sorts), then the default, deduped on the absolute, folded, lowercased path. `.app` rewriting on macOS. `ProgramData` falls back to `C:\ProgramData`. The 1 s stale-port probe. The `running`, `closed`, `unknown` rules.
- [x] The setting is `lcu_install_dir`, per the root (the plan's `league_install_dir` is wrong). T19 cannot read the database, so it is the `InstallDirSetting` trait, in memory until T20 backs it with `db`. A successful process lookup fetches `/data-store/v1/install-dir` and stores it, as `rememberInstallDir` does.
- [x] `process_lookup.rs`. `ps x -o args` on macOS with no shell and the `LeagueClientUx` filter in Rust. PowerShell `-NoProfile -Command Get-CimInstance ...` on Windows with `CREATE_NO_WINDOW`, and the elevated check the same way. league-connect's lookahead regexes are ported as matchers and tested against both formats. The 30 s spacing is set before the lookup starts, as `nextAuthenticateAt` is.
- [x] `status.rs`. Every `set` calls the emitter, changed or not. A `broadcast` channel carries only changes, in order. `emit_to_main` sends `lcu:status-changed` with `emit_to("main", ...)`, not to the card window.
- [x] `socket.rs` sends `[5,"OnJsonApiEvent"]` right after the handshake, inside the 15 s attach timeout. Frames that are not JSON arrays are skipped, the empty ack included. The opcode is not checked, as in `lcu.ts`.
- [x] `mod.rs` holds the connect loop. The first tick is 5 s after start, not at 0. Overrun ticks are skipped. The poll timer is installed before the first poll. The socket attaches from the poll, and the phase is read once after attaching. `applyPhase` never raises a disconnected status. A socket drop drops `ingame` to `connected`, then a phase request decides whether to restart. Restarts send `disconnected`. `stop_polling` stops everything and nothing restarts after it. T20 plugs in through `Hooks::on_poll`, where an error restarts the loop, and `Hooks::on_event`, which gets every event after the transport reads the phase and session. T19's own `TransportOnly` hook GETs `/lol-summoner/v1/current-summoner` and logs `returned 200`, which gives lane 2 its line and makes a TLS failure flap the status as Electron's sync does. `bytes` ports `lcuBytes`: it uses the lockfile only (never the process lookup), caches that for 5 s, runs at most 6 at a time in FIFO order, and times out at 5 s. `LcuError` keeps league-connect's and `lcu.ts`'s messages, and `friendly_message` ports `friendlyErrorMessage`, with `ConnectionLost` standing in for Node's `ECONNREFUSED|ECONNRESET|socket hang up|EPIPE`.
- [x] The `parity-ca` feature reads `BMT_PARITY_CA` (a PEM path, read again for every new set of credentials, because each fake run makes a new CA) and limits discovery to `BMT_PARITY_LEAGUE_DIR` alone. It ignores the setting, so a snapshot's real `lcu_install_dir` can never be read. Its process lookup reads `BMT_PARITY_PROCESS_ARGS` (a text file standing in for the process list) or finds nothing, and logs `parity: process lookup <n>`. A parity build with no variables set finds no client and reads nothing. `#[cfg(all(feature = "parity-ca", not(debug_assertions)))] compile_error!` in `tls.rs` stops a release build.

## Findings for the root

- `T19-how.md` says `attachEogListener` re-sends the status every 60 s through `applyPhase`. It does not. `pollTick` calls `attachEogListener` only when there is no socket, so the branch that re-reads the phase when one exists never runs in Electron. The port matches Electron's real behavior and sends no 60 s resend.
- T03's `parity/fake-lcu/ca.ts` fails about one start in a few hundred. `integer(crypto.randomBytes(16))` adds a zero byte when the high bit is set but never strips a leading zero, so some serials are non-minimal DER, and Bun's TLS refuses them with `ERR_OSSL_ASN1_INVALID_INTEGER` (`parity/out/T19/cycle/fake-3.log`).
- Public roots for SGP (T20) and Data Dragon (T22) are not in `tls.rs`. Those calls must not use the Riot-only config. Recorded as T20's and T22's job: add a `webpki-roots` config next to `config_with_anchors`.
- T08's `commands/lcu.rs` defines its own `LcuStatus` with serde. At wiring, `get_lcu_status` and `events::status_changed` should map from `lcu::LcuStatus`, or `lcu` should take T08's type.
- The plan's `parity-ca` "test builds only" became "debug builds only", the same rule T07 applies to `parity-driver`, so lane builds (`--debug`) can carry it.
