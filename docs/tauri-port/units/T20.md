## Design

The design input was a how run on the Electron code (`lcu.ts` 200 to 1339, `index.ts`, `ipc-handlers.ts`, the renderer's toast and Settings consumers, T19's transport, T03's scenarios, and T05's event goldens). The port follows `lcu.ts` function for function. The parts that are new:

- **The data shapes.** `GameSync` holds one `SyncState` under a mutex: `backfill_running`, `backfill_cancelled`, `auto_paused` (`None`, `Until(Instant)`, or `Forever`, for Electron's `0`, a time, and `Infinity`), `swept`, and `sgp_host`. `Eog` holds `eogPending` as a map from the game id to `Running` or `Scheduled(JoinHandle)`. No lock is held across an await.
- **The seams.** The sync talks to the client through a `Client` trait, which `Lcu` implements, and to Riot's match history service through an `Sgp` trait, which `HttpSgp` implements. `Env` supplies the database, champion data, the wall clock, and the three events. Tests use in-memory stand-ins on tokio's paused clock, so each request's time is exact.
- **JavaScript numbers.** Game ids stay `f64` from parse to bind. Ids from the client's list are bound as the raw JSON value through T11's `js::bind`, as better-sqlite3 binds them. `Number()`, `String()`, template literals, `||`, `?.`, and `includes` have helpers that follow JavaScript, including hex, octal, and binary literals, `-0` as a set key, and strict `includes`.
- **Champion data.** Per the root's rule from T12's verifier, every insert reads the classes of that moment from a `Champions` hook (`classes()` and `wait_for_champion_data()`, Dragon's API on `port/T22-assets`). The startup score backfill waits for champion data, runs `check_score_backfill`, and sends `lcu:games-updated` when it ran. Production code never uses `ChampionClasses::none()`. Until T22 is in the base, nothing manages the hook, so `start_polling` logs that and starts nothing, and an insert refuses.
- **The app.** A small plugin manages `LcuSync` once the app exists, the golden replay's mock app included. Polling starts in `run()`'s setup after the window is built, as `startPolling(win)` follows `createWindow()`.
- **Parity.** A `parity-ca` build sends `*.pp.sgp.pvp.net` requests to `BMT_PARITY_SGP_URL` with path and query kept, as `seam.cjs` redirects Electron's `fetch`. Without the variable, nothing is sent and the request fails with `fetch failed`.

## Build

- [x] Port the poll body and the recent-games sync. `sync_games` runs the once-per-launch full sweep unless the phase is `InProgress` or `Reconnect`, and on a sweep failure falls back to the window and pauses the sweep for 15 minutes. `fetch_new_games` reads the twenty-game list by puuid, then the current-summoner list, and stores, ignores, or skips each game as Electron does. A full window with nothing known escalates to a non-full walk. The 5 s connect loop and the 60 s poll are T19's. T20 runs inside `Hooks::on_poll`, which returns at once while a backfill runs.
- [x] Port the SGP backfill with shard probing and cancel. The probe tries the region's shard first, then the others in `SGP_HOSTS` order, with 8 s per probe. Only a shard that returns a game is remembered, in memory and in `sgp_host`. Pages are 200 ids with 30 s each, up to 25 pages. A 401, 403, or 404 rehomes and walks again. An empty walk rehomes once. The oldest-game probe sets `limit: service`. Cancel is checked before each game's request. `lcu:backfill` returns `BackfillOutcome` as data, `lcu:cancel-backfill` and `lcu:backfill-running` answer from the same state, and the progress and done events carry T08's payloads.
- [x] Port end-of-game capture over the socket. `EndOfGame` with a remembered session, or either stats-block path, starts a capture unless the game is pending or stored. A queue outside Mayhem is ignored without a request. A failure retries 2, 5, 15, 60, 120, and 120 s after it, then gives up. Success sends `lcu:games-updated`.
- [x] Wire the quit to the final fetch with the 5 s cap. `LcuSync::final_fetch` and `LcuSync::stop_polling` are the functions T10's hooks call. Until T10 lands, `lib.rs` runs them from `RunEvent::Exit`: the bounded fetch, then stop polling, then `Shutting down`, then close the database.

### Dock Quit and logout on macOS

T10 found that Dock Quit and logout skip the final fetch, because tao never turns `terminate:` into `ExitRequested`. There is a public-API way to run it. tao's `applicationWillTerminate:` calls `AppState::exit`, which sends `Event::LoopDestroyed` (`tao-0.37.3/src/platform_impl/macos/app_delegate.rs:76`, `app_state.rs:271`), and tauri-runtime-wry turns that into `RunEvent::Exit` (`tauri-runtime-wry-3.0.0-alpha.6/src/lib.rs:4321`). AppKit ends the process only after that delegate method returns, so a `RunEvent::Exit` handler that blocks on the fetch keeps it alive.

- Evidence: `parity/out/T20/terminate-proto/` is a windowless tao program with activation off. It queues `terminate:` on the main run loop, as the Dock's Quit arrives, then blocks on 2 s of tokio work in `LoopDestroyed`. The work finished, and the process exited 0 after it (`run.log`: `1140 ms: LoopDestroyed`, `3143 ms: the awaited work finished`, `exit=0`).
- Caveat, measured: calling `terminate:` from inside tao's own event callback deadlocks, because `AppState::exit` takes the callback lock the caller holds. The Dock and logout never call from inside it.
- For the restack: in `RunEvent::Exit`, when T10's shell phase is still `Running`, call `shell.begin_quit()`, wait on its fetch with `lcu::sync::wait_for_final_fetch`, then `shell.finish()`. `lib.rs::quit` already does the first half.

## Fix round 1, from an independent audit

An audit agent compared the port to `lcu.ts` before the code-ready report.

- [x] HIGH. `lib.rs::quit` built the 5 s timer outside the runtime, which panics on the main thread, so the final fetch never ran on a connected quit. The timer is now built inside `block_on`, in `lcu::sync::wait_for_final_fetch`, and a test proves the old code panics.
- [x] LOW. A non-JSON match history body failed with serde's text. It now fails with V8's messages (`Unexpected end of JSON input`, `Unexpected token '<', "<html>" is not valid JSON` with V8's ten-character context, `Unexpected non-whitespace character after JSON at position N`), and a byte order mark is dropped first, as undici does.
- [x] LOW. The rolled-over escalation checked `backfill_running` and claimed the walk in two steps, so a manual backfill starting in between could cost a 15 minute pause Electron never takes. It now checks and claims in one step.

## Findings for the root

- T03's `loadContext` closes its database before a known game's detail is first asked for, so the fake answers 500 for every known game. Lane 6 needs a known game's detail, so `tools/t20-run.ts` serves known games from the untouched fixture copy itself.
- T03's `run-electron.ts` quits Electron with `app.exit(0)`, which skips `before-quit` and so the final fetch. Lane 6 and lane 10 of T10 need `app.quit()`, which `tools/t20-run.ts --quit` calls.
- The seam freezes `Date.now()` in Electron's main process, so in lanes Electron's 15 minute sweep pause and 30 s process lookup spacing never lapse. The port uses a monotonic clock, so they do. Lanes shorter than 15 minutes are unaffected.
- `MAYHEM_LAUNCH` comes from T11's `season_bounds`, which reads the process time zone, as Electron does. The rule asks for one explicit zone source. That is T11's call.
- `isMatchUnderway` in `lcu.ts` is the updater's (T24) and is not ported here. It is a phase request through `Lcu::request_json`.
- `BackfillLimit::Service.history_start` is T08's `i64`. Electron sends `Number(gameCreation)`, so a fractional value would differ. Real values are whole milliseconds.
