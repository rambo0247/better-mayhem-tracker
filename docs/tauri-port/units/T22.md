## Build

- [x] `dragon.rs` ports `dragon.ts` for `dragon:champions`, `dragon:augments`, `dragon:augment-icon`, `dragon:items`, `dragon:summoner-spells`, plus `loadSummonerSpellKeys` for T21. Same hosts and URLs, `User-Agent: BetterMayhemTracker/1.0`, 10 s timeout. `data/champion-cache.json` is written in Electron's exact bytes (test asserts the string) and read back for offline starts. `data/augment-icon-cache.json` keeps Electron's key order (integer keys ascending, then insertion order), drops patchless misses, and rewrites old CommunityDragon hits to `asset://` on read. Memo and retry rules match: augments from a fallback branch are served once and not kept, items keep the fallback under the patch's label (Electron's bug, kept), failed loads retry. The icon walk keeps the 12-branch lookback, 4 lookups at a time, the conclusive and inconclusive split, and writes nothing unless the live export lacks the art.
- [x] `assets.rs` ports `game-assets.ts`. Disk first, then CommunityDragon, then the client, then another patch's copy for art. "latest" game data goes network first. Eight remote requests at a time in FIFO order, a 30 s outage backoff on a network error or 5xx (not on 429), the 60 s "which patch is latest" retry from `content-metadata.json`, the 10 s client patch retry reset on any LCU status change, the session `missing` set, and one in-flight load per file and mode. Answers are 200 with a sniffed `Content-Type`, 400 for any URL the builders don't make, 404 for missing, 503 for no answer.
- [x] `asset_cache.rs`. `asset-cache/<patch>/<sha1 of game path><ext>`, temp file and rename, mtime touched at most daily on read, prune 60 s after start then every 24 h: over 256 MiB, least recently used goes until 192 MiB; stray `.tmp` older than 1 h always goes; then empty folders go.
- [x] Public TLS. `public_tls_config()` in `assets.rs` is its own rustls config over `webpki_roots::TLS_SERVER_ROOTS` with the ring provider. `lcu/tls.rs` is untouched and still trusts only Riot's root. A test asserts the public store holds no Riot root.
- [x] Parity builds use `ParityWeb`: every request fails as a blocked fetch, unless `BMT_PARITY_WEB` names a loopback base, then `https://<host>/<path>` goes to `<base>/<host>/<path>`.
- [x] Traversal. The parser decodes each segment strictly (malformed escape or non-UTF-8 is a 400, as `decodeURIComponent` throws), refuses any segment that is all dots or holds `/`, `\`, `:` or NUL after decoding, allows only `latest`, `pbe` and `NN.NN` branches, and applies Electron's image path regex. Copies are always read at `root/<patch>/<hash>`, so no request can name a file outside the cache. Electron's URL parser would resolve `..` instead of refusing it. Refusing is stricter and was the root's order.
- [x] Windows. WebView2 routes custom schemes only as `http://<scheme>.localhost` (wry's filter). The scheme handler reads both forms: for host `asset.localhost`, the first path segment is the kind. `asset-url.ts` rewrites `asset://` to `http://asset.localhost/` under WebView2 for the Solid UI. URLs a command returns (a resolved augment icon) go through `assets::for_webview` at the command boundary, so stored files keep `asset://` and stay Electron's. Unproven on `windows-latest` until lane 2 runs.

The app registers the load in setup (`load_champion_data`) before anything can wait, so Electron's `waitForChampionData().then(checkScoreBackfill)` is, in Rust, a task spawned after `dragon.start()` that awaits `wait_for_champion_data()`, calls `check_score_backfill(conn, &dragon.champion_classes())`, and emits `lcu:games-updated` when it returns true. A test asserts a waiter registered before `start` sees the loaded classes.

Reading `Dragon::champion_classes()` gives the same data, plus the in-memory value when the file write failed, which is what Electron's teammates code reads (`getChampionClasses()`).
