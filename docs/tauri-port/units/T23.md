## What landed

- `tauri/src-tauri/src/autostart.rs` ports `autostart.ts` by hand, per E7.
  - macOS writes `~/Library/LaunchAgents/com.better-mayhem-tracker.app.autostart.plist` byte for byte as Electron does, with `<bundle>/Contents/MacOS/<exe> --hidden` and RunAtLoad.
  - Windows writes the HKCU Run value `better-mayhem-tracker` as Electron's `setLoginItemSettings` does. The data goes through a port of Electron 44.4.5's `AddQuoteForArg` (`shell/common/command_line_util_win.cc`), which gives `"<exe>" --hidden` for any exe path. Enabling deletes the StartupApproved value and disabling deletes both values, as `Browser::SetLoginItemSettings` (`shell/browser/browser_win.cc`) does. Registry failures are ignored, as Electron ignores them.
  - `auto_start_path` records the last registered target. A launch rewrites only an entry that moved, so a player who disabled the app in Task Manager stays disabled.
  - `LoginItems` names where entries go. `System` is the user's LaunchAgents under `HOME` (Node's `os.homedir()` reads `HOME` first, and so does `dirs`) and HKCU. `At` is a scratch folder and scratch HKCU subkeys. `Recorded` lists writes for golden replay on any OS. It has the same shape as T09's `Effects`, which this unit does not edit, so the next T09 merge stays trivial.
- `tauri/src-tauri/src/shortcut.rs` ports `shortcut.ts` with the `windows` crate. The process takes AppUserModelID `com.better-mayhem-tracker.app` through `SetCurrentProcessExplicitAppUserModelID`. `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Better Mayhem Tracker.lnk` is rewritten unless it already targets this exe with that id. The id is written as `VT_LPWSTR`, as Chromium's `InitPropVariantFromString` does.
- `commands/settings.rs`: `setSetting("auto_start")` now registers the login item, which closes T11's W2. `autostart:supported` answers `install_location::has_durable_install()`.
- `lib.rs`: setup sets the app id, checks the shortcut, and syncs the login item before the window opens.
- `tauri.conf.json`: `mainBinaryName` is `Better Mayhem Tracker`.
- `Cargo.toml`: `windows =0.62.2`, the version already in the lock, with the Registry, Shell, COM, and property-store features. No new crate version.
- `parity/autostart-golden.ts` records Electron's output. `parity/autostart-review.ts` runs the macOS lanes and renders the review media.
- Outside the section, approved by the root: `parity/run-tauri.ts` and `.github/workflows/tauri-ci.yml`, because `tauri build` moves the binary to `mainBinaryName`. `tauriBinary()` takes whichever name exists, the newer when both do, and names both when neither does (`parity/test/tauri-binary.test.ts`, 5 tests). All four `exe=` lines in tauri-ci.yml follow a `tauri build` and take the new name.

## Is the registered path Electron's?

- macOS: yes. Electron registers `<bundle>/Contents/MacOS/` plus `basename(process.execPath)`, and electron-builder names that executable `Better Mayhem Tracker`. Tauri registers `<bundle>/Contents/MacOS/` plus `current_exe()`'s file name, which `mainBinaryName` makes `Better Mayhem Tracker`. Lane 9 shows that an Electron-written LaunchAgent for the same bundle is left byte-identical and unrewritten. The path stays the same only if T24 puts the Tauri bundle where the Electron bundle was.
- Windows: it depends on T39 and T24. Electron registers `PORTABLE_EXECUTABLE_FILE`, which is the exe the player keeps, `BetterMayhemTracker.exe` as downloaded. Tauri registers `current_exe()`. `mainBinaryName` makes the built exe `Better Mayhem Tracker.exe`. If the release or the hand-off keeps the player's file at `BetterMayhemTracker.exe`, the Run value data is unchanged. If the path changes, the first Tauri launch rewrites the same value name to the new path. That makes one entry, not two, but it resets the StartupApproved value, as Electron does after a move. The shortcut target follows the same rule. This is a parity item for T39 and T24.

- Lane 1, PASS (`plist-diff.log`, `T23-review-plist.png`). The lane build, launched from a scratch bundle with `auto_start` true, wrote a LaunchAgent byte-equal to Electron's for that bundle. Against Electron's `/Applications` output, only the one `ProgramArguments` path line differs.

- Lane 9, PASS (`inherited-plist.log`, `T23-review-inherited.png`). Electron's LaunchAgent and `auto_start_path` were already present. After a Tauri launch, the file kept the same bytes and mtime, and there is one agent.
- Lane 10, PASS for `autostart:supported` (`golden-table.log`). Two rows fail, and both fail identically at the integration base without T23 (`golden-table-base.log`). They are `settings:get` (3 state cases, values the states set) and `window:is-maximized` (the mock runtime, T10's known item).

How the macOS lanes stay off the operator's machine:

- The lane build is a dev build with `debug-assertions` off and `custom-protocol`, so `install_location` treats it as installed, as it does a release build.
- It runs from a scratch `.app` with its own bundle id, `com.better-mayhem-tracker.lane-t23`, and `HOME` pointing at a scratch folder.
- Its data folder and LaunchAgents folder both resolve under `HOME`. The script checks that the app logged into the scratch data folder before it trusts a result.
- WebKit ignores `HOME` and keeps website data and caches under the real `~/Library/{WebKit,Caches}/<bundle id>`. The script refuses to run if those folders already exist and removes them at exit. None remain.
