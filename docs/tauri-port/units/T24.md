## What landed

- `tauri/src-tauri/src/updater.rs`, a direct port of `src/main/updater.ts` (E6).
  - Pure decisions: `parse_version`, `compare_versions` (`[0-9]` digits, each part as JS's `Number`, one leading `v`, JS `trim`), `to_release_note` (CRLF, the `**Full Changelog**` line, the 4,000 UTF-16 unit cap with `…`), `is_install_asset` (`BetterMayhemTracker-mac-<arm64|x64>.zip`, else the first `.exe`), `parse_digest`, `Page::from_body` (drafts, prereleases, and entries without a string tag are dropped, parsed leniently from `serde_json::Value`), `evaluate`, `release_notes_between`, `launch_version_change`.
  - The install flow runs against a `Host` trait: page fetch, download, settings, install target, window visible and minimized (two checks, since `relaunchHidden` is `!isVisible()` and "in use" is visible and not minimized), match underway, backfill running, emit, log, apply, quit. The app's `AppHost` implements it over Tauri state; the tests use a fake.
  - `download_and_install` claims the single-flight flag with `compare_exchange` and leaves it set on success. The cached URL and digest are read under one lock. The 30 s stall timer wraps the request and every chunk, so a server that never sends headers also ends in "Download stalled". The temp folder is `better-mayhem-update-XXXXXX` under the temp dir, kept on success for the script to remove, removed on every failure.
  - The launch install, the 45 minute interval (`interval_at(now + 45 min)`, `MissedTickBehavior::Delay`, so no tick at launch and no burst after sleep), and the 2 minute settle re-armed on each put-away are on `tokio::time`. `Shell::on_put_away` only sends on a channel, so nothing runs under the shell's hook lock.
  - Swaps: `apply_mac_update` (ditto into `.<bundle>.update`, first `*.app`, `update.sh`, `/bin/sh` spawned in a new session with `setsid`, the analogue of Node's `detached`), `apply_windows_update` (`update.cmd`, `cmd.exe /c` with `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`). ditto and the script writes run in `spawn_blocking`.
  - Quit: `shell::request_quit` 200 ms after the swap starts, which runs the final fetch and closes the database. The script waits on `std::process::id()`.
  - `record_launch_version` runs right after the database opens, before the login item sync, as `index.ts` orders it. `start` runs last in setup: the launch install, then the background schedule.
  - `Github`: the real hosts in release builds, nowhere in golden replay (`Effects::Recorded`, since T05 recorded Electron with the network blocked), and in parity builds only a loopback fake named by `BMT_PARITY_GITHUB`, using `assets.rs`'s `parity_web` convention (`<base>/<host>/<path>`, `no_proxy`). A parity build with no fake reaches no host. The prefix check and the cached URL run on the github.com URL.
- `tauri/src-tauri/src/mac_update_script.rs`: `mac-update-script.ts` byte for byte. `tests/fixtures/electron-update-scripts.json` holds the TS output for the smoke test's quote-in-path case and a plain case, written with `bun` from `src/main/mac-update-script.ts`. The Windows script is compared with `updater.ts`'s lines in a unit test on every OS.
- `commands/app.rs`: `app:check-update`, `app:download-update` (no `canRestart`, as the Update button has none), `app:launch-install`, `app:update-notes`. The `update:*` events go through `events.rs`'s emitters.
- `lib.rs`: the modules, `updater::State` managed in `app_builder`, `record_launch_version` and `start` in setup, and two parity-only seams.
  - `BMT_PARITY_VERSION`, read by `option_env!` at build time in parity-driver builds only, gives a lane build its release version, since `app_version()` reads the root `package.json` (1.2.1) and T01 to T40 may not edit it.
  - With `BMT_PARITY_PACKAGED=1` (parity builds only), the login item goes under the data root's `LaunchAgents` and scratch HKCU keys, never the user's.
- `parity/fake-github.ts` (T04's file, imported unchanged in `036bfee`, then edited): `--latest <tag> --asset <name>=<file> [--bad-digest]` serve real build files with their true size and sha256 (or all zeros), a download answers 302 to `localhost`, as GitHub sends assets on to its objects host, and paths are served bare for the Electron seam and under the host for the Tauri parity build. `parity/test/fake-github.test.ts` covers it.

## Interrogate

Run once on the hand-off design (`_design/T24-handoff-decisions.md`) before the build, with the configured panel: Reviewer A opus at medium, Reviewer B sonnet at high, Reviewer C haiku at high, each read-only.

Acted on, and where:

- A parity build could reach the real GitHub when a lane forgot the fake (A, B). Parity builds fail closed and take only a loopback base.
- `BMT_PARITY_EXEC_PATH` took any path and bypassed the detection code (A, B, C). Replaced by `BMT_PARITY_PACKAGED`, which flips only "packaged". Lanes run the binary from inside a scratch `.app`, so `current_exe`, `canonicalize`, and `bundle_of` are the release's. A parity build refuses a bundle under `/Applications` or `~/Applications`. Its login item goes under the data root.
- The stall timer missed the header phase (A, C). It wraps `send()` too, and a test covers a server that never answers.
- `tokio::time::interval` ticks at once and bursts after sleep (A, B, C). `interval_at` with `Delay`.
- Single flight by load-then-store, and a URL and digest read across two locks (A, B, C). `compare_exchange`, one lock.
- `tempfile` would delete the folder before the script used it (B, C). A plain folder, removed only on failure.
- The shell holds its hook lock while it calls listeners (B, C). T24's listener only sends on a channel. `shell.rs` is unchanged.
- `relaunchHidden` and "window in use" are different checks (A). Two host methods.
- Strict serde parsing would fail a whole page on one odd release (B). The page is `serde_json::Value`.
- Node's `detached` is `setsid` (A, B). `setsid` in `pre_exec`. `CREATE_NO_WINDOW` is ignored with `DETACHED_PROCESS` (B, C), so the Windows flags are `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`; unverified on Windows.
- `app.isPackaged` is a getter (A, B, C). The hand-off seam sets it with `Object.defineProperty` and fails if it does not read back true.
- The lane would have patched Electron after `whenReady`, so only the manual path ran (A). The seam is a `-r` preload, so lane 1 exercises the launch install, hidden, as a login launch does.
- Lane isolation by prose (B, C). The hand-off seam loads `seam.cjs` first, so its real-folder guard keeps the real home, then moves `os.homedir()` to a scratch folder and refuses an exec path in an Applications folder. `updater-lanes.ts` checks the fixture has no `auto_start` keys before each lane, and the hand-off lane uses the same fixture.
- Dynamic error strings cannot be byte-identical (A, B). See "Strings that differ" below.
- `live.rs`'s `expect(dead_code)` on the match helpers (A). Removed.
- The fake never redirected (C). It answers 302 to `localhost`.
- Lane 1 must read the executable from the swapped Info.plist and pass the recorded arguments (A, C). It does, and checks `codesign --verify --deep --strict` and `lipo -archs`.

Considered, for the root:

- Release builds take their version from `package.json`, and `tauri.conf.json`'s `version` is still `0.0.0`, so a release built without `--config '{"version":...}'` ships `CFBundleShortVersionString` 0.0.0 (A, C). `app_version()` itself is right once T41 bumps `package.json`. Pointing `tauri.conf.json`'s `version` at `../../package.json` would make one source. That file is outside T24's list. Decision R1.
- The WebView2 check (E8) is still T39's. 1.2.1 deletes the Electron exe and starts the Tauri one with no check, so a Windows player without WebView2 loses the app at the hand-off (B, C). Decision R2.
- T24's Windows apply path has no live lane (A, B, C). See lane 2.

Noted: a 1.2.1 trace through a fake clock as an oracle for the schedule (C) was not built; the schedule tests read the TS by hand. 1.2.1's background and launch installs can race on `installInProgress` (C); kept as Electron has it. A schedule-duration override for lanes (B) would change the schedule under test; not added.

Dismissed: splitting `updater.rs` into submodules (C), since the plan names one file. Running every lane under T23's Seatbelt profile (A) is covered differently: the Tauri lanes' login item goes under the data root, and the Electron lane's `os.homedir()` is scratch.

## Strings that differ from Electron

Every fixed string is byte-identical. Three carry an error message from the platform, and those differ:

- `Download failed: ${err.message}`: transport failures read `Download failed: fetch failed`, which is Node's text for every fetch failure. A file write failure carries Rust's `io::Error` text.
- `Failed to create temp dir: ...` and `Can't write next to <name>: ... Download it manually instead.` carry Rust's `io::Error` text where Node's reads `EACCES: permission denied, mkdtemp '...'`. No golden holds either.

## Kept from 1.2.1, for the root

- 1.2.1's Windows `update.cmd` does not check `move`'s errorlevel. A `move` that fails after the delete loop leaves no exe at the target, and `start` silently fails. R3 resolved on port/integration: ours copies the old exe aside first, and a failed `move` puts it back and starts it (`a_failed_move_puts_the_old_exe_back_and_starts_it`, and on Windows `on_windows_a_failed_move_puts_the_old_exe_back`). 1.2.1's own script, which runs the 1.2.1-to-Tauri swap, is unchanged.
- `installInBackground` checks `installInProgress` only at entry, as Electron does.

## Perf

- Metric: the update's download size, and the time from the install starting to the relaunched window.
- Download size. The release build (`CI=true bun run tauri build --bundles app`, no driver) zips to 4,412,935 bytes for arm64, against Electron 1.2.1's `BetterMayhemTracker-mac-arm64.zip` at 117,026,414 bytes (T06, from `gh release view v1.2.1`). PASS against the 10 MB rule. The release binary holds none of `BMT_PARITY_GITHUB`, `BMT_PARITY_PACKAGED`, `BMT_PARITY_VERSION`, `BMT_DATA_ROOT`, or the driver sentinel. The lane zips are debug builds (16.3 MB) and are not the number.
- Time, measured on the operator's Mac with debug lane builds.
  - Tauri to Tauri (lane 3, 5 runs, `perf-tauri-to-tauri.json`): from the `Installing update 1.3.1 on launch` line to the relaunched window built, 1,492 to 1,573 ms, median 1,558. Of that, 1,226 to 1,292 ms is until the script calls `open`, most of it the script's 1 s `kill -0` poll and the quit; the window builds 266 to 297 ms after the relaunch starts.
  - Electron 1.2.1 to Tauri (lane 1, 5 runs, `handoff-mac.json`): from starting Electron to the relaunched Tauri window, 2,372 to 2,708 ms, median 2,505. This includes Electron's own startup.
  - Electron 1.2.1 to Electron 1.2.1 (baseline, 3 runs, `handoff-baseline-electron.json`, the same lane with `--baseline` offering the real 1.2.1 zip): from starting Electron to the script's `open` call, 3,101 to 3,138 ms, before Electron's own relaunch, whose launch to first content is 982 ms median in T06. So about 4.1 s against Tauri's 2.5 s on the same path.
  - PASS: the relaunch is faster than Electron's. These are three short series on a busy machine; the limiter in each is the script's 1 s poll plus the download and unpack (117 MB for Electron), so the gap is mostly the zip size.
