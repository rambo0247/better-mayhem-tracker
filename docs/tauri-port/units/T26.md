# T26 Carry localStorage over from Electron

Branch `port/T26-localstorage`, based on `port/T09-paths` at bd1ceb4. Tip SHA: see the report; the record is committed with the code it describes.

## What changed

- `tauri/src-tauri/src/local_storage.rs`: copies `<root>/Local Storage/leveldb` to a scratch folder (minus `LOCK`), opens only the copy with `rusty-leveldb` 4.0.2 (pinned), keeps `recap-badge-seen` and every `view:` key under origin `file://`, decodes values by their first byte (`0` UTF-16LE, `1` latin1).
- `lib.rs`: runs the import in `setup` before the window is built and adds an initialization script that fills only missing keys, once per tab (`sessionStorage` flag). The log line reports the keys carried and the milliseconds taken.
- The "ran" record is `<root>/data/local_storage_imported.json` (`at`, `outcome`, `carried`, `reason`). A store with nothing to carry (no store, no `CURRENT`, or no carried keys) and a corrupt store (LevelDB `Corruption`) are recorded at once. A store with pairs is recorded only when the page's fill script has set every key and reports it through `page_event` (`local-storage-filled`). Until then no marker exists, and a relaunch reads the store again and refills only the keys the webview lacks. Every other failure (copy error, full disk, lock, a missing manifest file) writes nothing, so the next start retries.
- The fill script sets its `sessionStorage` flag and reports only after the loop, so a reload after a failed fill tries again.
- `Scratch` names folders by pid, an atomic counter, and nanos, and creates with `create_dir`, so a name that exists is never shared (the old pid and nanos name collided across test threads on macOS).
- `parity_driver.rs`: `BMT_PARITY_PERSIST=<32 hex>` turns incognito off and names a scratch WebKit data store, so a lane can see values survive a relaunch. Without it every launch stays incognito.
- Fixture: `tests/fixtures/local-storage/` holds a store written by trunk Electron through `parity/run-electron.ts` (`generate.ts`) and `expected.json`.

## Decisions for the root

- The plan says a `local_storage_imported` setting. The settings table is T11's and is not on this base, so the record is a marker file in the data folder. When T11 lands it can read that file or replace it. Electron 1.2.1 ignores it.
- `api.ts` is not edited. An initialization script runs before any page script, which is earlier than the UI's first read.
- The import takes every `view:` key, not an allowlist, so a key Appendix F misses still moves. This matches Electron, whose `readViewState` and `clearViewState` treat the whole `view:` prefix as view state.
- The marker stays a file. The plan names a `local_storage_imported` setting, but T11 is not on this base. The restack moves the marker to T11's setting by replacing the two functions in the `marker` module (`exists`, `write`) and nothing else.
- Only `Corruption` is a permanent skip. A store whose `CURRENT` names a manifest file that is gone fails with `NotFound`, so it is retried on every launch and never recorded. The root may decide to treat that as permanent.
- WebKit persists `localStorage` lazily, so a crash after the page confirms and before WebKit flushes can still lose the values. The confirm narrows the window to that flush, it cannot close it.
- The recap badge never shows on the fixture at the frozen clock, so lane 2 proves the value carried, not a suppressed badge.

## Verify, unit

PASS. `cargo test --lib local_storage`: 14 tests, 50 back-to-back runs with no failure (the test binary run 50 times, and `cargo test --lib local_storage` 50 times). They read the Electron-written store (latin1 values including a byte above 0x7f, UTF-16 values, bookkeeping keys, a removed key, an unrelated key) and assert the 58 imported pairs equal `expected.json`; assert the source folder is byte-identical after a read; no marker before the page confirms, marker after; a stub that never confirms leaves no marker and the next start imports the same pairs, then confirms once; a failed marker write keeps the confirmation pending; no-store and empty folder are final at once; flipped and truncated manifests are skipped for good; only `Corruption` classifies as permanent; an unreadable file in the store (failed copy) and a `CURRENT` that names a missing manifest leave no marker and retry; 1,600 scratch folders across 8 threads never collide; byte flips and truncations of every fixture file never panic; the script fills only missing keys and reports only after setting the flag. `parity_driver::tests` (feature `parity-driver`) checks the store id parser. `TZ=UTC cargo test` passes.
