### Local patches the run needed, not committed

Three integration defects stopped the Tauri side before any state ran. The run used local patches, saved in `parity/out/report/local-patches.diff`. None is committed, because each file belongs to another unit.

1. `parity/run-tauri.ts` `refuseProductionIdentifier` refused every driver build, because T23's LaunchAgent label `com.better-mayhem-tracker.app.autostart` contains the production id. The patch matches the id only when no `.`, word character or `-` follows it.
2. `tauri/src-tauri/src/parity_driver.rs` asserts the identifier equals `com.better-mayhem-tracker.parity`, but `shell::scope_identifier` (the root's decision) appends a per-data-root hash. The patch accepts `com.better-mayhem-tracker.parity.<hash>`.
3. `tauri/src/lib/api-shim.ts` still exports `window.api ?? notPortedApi()`, and nothing in the Solid app calls `install()` from T08's `src/api.ts`. So the integrated app reaches none of its Rust commands, and every page call rejects `not ported`. The patch exports `window.api ?? (window.__BMT_BOOT__ ? install() : notPortedApi())`. It also makes `run-tauri.ts` wait for `window.api` after the reload. This is the largest finding: without it the Tauri app shows no data.
